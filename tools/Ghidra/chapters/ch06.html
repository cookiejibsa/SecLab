PCode — 왜 존재하는가

x86 어셈블리는 수백 가지 명령어가 있다. ARM은 다른 수백 가지. MIPS는 또 다르다. 이 모든 아키텍처에서 "이 값이 어디서 왔는가", "이 함수의 반환 타입이 뭔가"를 분석하려면 아키텍처별로 분석 코드를 따로 작성해야 할까? PCode는 그 문제를 푼다.

PCode는 Ghidra의 내부 중간 표현(Intermediate Representation) 언어다. 모든 아키텍처의 명령어가 PCode로 "리프팅(lifting)"된다. PCode는 ~70가지 연산자만 있고, 명확하게 정의된 의미론(semantics)을 갖는다. 분석 로직은 PCode를 대상으로 작성하면 어떤 아키텍처에서든 동작한다.

ADD     EAX,EBX
; ---PCode---
;  (u0:4) = INT_ADD EAX, EBX
;  CF = INT_CARRY EAX, EBX
;  OF = INT_SCARRY EAX, EBX
;  SF = INT_SLESS (u0:4), 0:4
;  ZF = INT_EQUAL (u0:4), 0:4
;  EAX = COPY (u0:4)

; → ADD 명령어 하나가 6개의 PCode 연산으로 변환됨
; → 플래그 레지스터 업데이트도 명시적으로 표현됨

Varnode — PCode의 기본 데이터 단위

PCode에서 모든 값은 Varnode로 표현된다. Varnode는 (메모리 공간, 오프셋, 크기)의 튜플이다. 메모리 공간은 레지스터 공간, 실제 RAM, 상수 공간, 유일 공간(임시값) 등으로 나뉜다. 

# Varnode 예시 (스크립트에서)
from ghidra.program.model.pcode import PcodeOp, Varnode

# 특정 함수의 모든 PCode 연산 순회
func = getFunctionAt(toAddr(0x401234))
decompiler_results = decompileFunction(func, 60, monitor)
high_func = decompiler_results.getHighFunction()

# High-level PCode (SSA 형태) 순회
opiter = high_func.getPcodeOps()
while opiter.hasNext():
    op = opiter.next()
    
    mnemonic = op.getMnemonic()            # PCode 연산자 이름
    output   = op.getOutput()              # 출력 Varnode
    inputs   = [op.getInput(i) for i in range(op.getNumInputs())]
    
    if mnemonic == "CALL":
        target = inputs[0]
        print(f"함수 호출: {target}")
    
    elif mnemonic == "INT_XOR":
        # XOR 발견 - 암호화 루틴 후보
        print(f"XOR 연산 at {op.getSeqnum().getTarget()}")

PCode를 이용한 데이터 흐름 분석

"이 변수의 값이 어디서 왔는가?" — 데이터 흐름 분석(Data Flow Analysis)의 핵심 질문이다. 고수준 PCode(SSA 형태)에서 Varnode를 역추적하면 값의 출처를 찾을 수 있다. 

#@title Trace Value Origin
#@category Analysis
# 특정 함수 호출의 첫 번째 인자 추적

from ghidra.app.decompiler import DecompInterface
from ghidra.util.task import ConsoleTaskMonitor

def get_decompiler():
    iface = DecompInterface()
    iface.openProgram(currentProgram)
    return iface

def trace_varnode_origin(varnode, depth=0, max_depth=10):
    """Varnode의 정의(definition)를 역추적한다"""
    indent = "  " * depth
    
    if depth > max_depth:
        print(f"{indent}[최대 깊이 도달]")
        return
    
    if varnode is None:
        return
    
    # 상수인 경우
    if varnode.isConstant():
        print(f"{indent}[상수] 0x{varnode.getOffset():X}")
        return
    
    # 정의 PCode 연산 찾기
    def_op = varnode.getDef()
    if def_op is None:
        print(f"{indent}[입력 파라미터 또는 전역]")
        return
    
    mnemonic = def_op.getMnemonic()
    print(f"{indent}[{mnemonic}] at {def_op.getSeqnum().getTarget()}")
    
    # 입력 Varnode들도 재귀적으로 추적
    for i in range(def_op.getNumInputs()):
        inp = def_op.getInput(i)
        trace_varnode_origin(inp, depth + 1, max_depth)

# 사용 예: check_password 함수의 첫 번째 인자 추적
iface = get_decompiler()
func = getFunctionAt(toAddr(0x401234))
result = iface.decompileFunction(func, 60, ConsoleTaskMonitor())
high_func = result.getHighFunction()

# 첫 번째 PCode 연산의 첫 번째 입력 추적
opiter = high_func.getPcodeOps()
if opiter.hasNext():
    first_op = opiter.next()
    print("=== 값 추적 시작 ===")
    trace_varnode_origin(first_op.getInput(0))

PCode 에뮬레이션 — 코드 실행 없이 값 계산

Ghidra의 PCode 에뮬레이터를 사용하면 실제로 코드를 실행하지 않고도 특정 함수의 결과를 계산할 수 있다. 악성코드의 복호화 루틴, CrackMe의 비밀번호 검증 함수를 에뮬레이션하는 데 쓴다. 

#@title PCode Emulation Example
#@category Analysis

from ghidra.app.emulator import EmulatorHelper
from ghidra.program.model.address import Address

# EmulatorHelper 초기화
emu = EmulatorHelper(currentProgram)

try:
    # 분석할 함수 주소
    func_addr = toAddr(0x401234)
    
    # 레지스터 초기값 설정
    emu.writeRegister("EAX", 0x1234)      # 첫 번째 파라미터
    emu.writeRegister("ECX", 0x5678)      # 두 번째 파라미터
    
    # 스택 포인터 초기화 (가상 스택 공간)
    emu.writeRegister("ESP", 0x00100000)
    
    # 특정 주소에서 실행 시작
    emu.setExecuteAddress(func_addr)
    
    max_steps = 1000
    steps = 0
    
    while steps < max_steps:
        # 한 스텝 실행
        success = emu.step(monitor)
        if not success:
            break
        
        steps += 1
        cur_addr = emu.getExecutionAddress()
        
        # RET 명령어 감지 (함수 종료)
        instr = currentProgram.getListing().getInstructionAt(cur_addr)
        if instr and instr.getMnemonicString() == "RET":
            break
    
    # 결과 읽기
    eax_result = emu.readRegister("EAX")
    print(f"함수 반환값 (EAX): 0x{eax_result:X}")
    print(f"실행된 스텝 수: {steps}")

finally:
    emu.dispose()  # 반드시 dispose 호출
⚠️
PCode 에뮬레이션의 한계

시스템 콜, Windows API 호출, 외부 라이브러리 함수는 에뮬레이션이 안 된다. API 호출 지점에서 에뮬레이션이 멈추거나 예외가 발생한다. 이런 경우 API 호출 바로 전후에서 에뮬레이션을 시작/중단하고 레지스터 상태만 분석하는 방식을 쓴다.

Headless Analyzer — GUI 없는 대량 분석

수백 개의 바이너리를 분석해야 할 때 Ghidra GUI를 하나하나 열기는 불가능하다. analyzeHeadless는 커맨드라인에서 Ghidra를 실행하는 방법이다. CI/CD 파이프라인, 악성코드 자동 분석 시스템에서 핵심적으로 쓰인다. 

# analyzeHeadless 기본 문법
# [Ghidra 설치 경로]/support/analyzeHeadless

# 단일 파일 분석
./analyzeHeadless \
    /tmp/my_project MyProject \        # 프로젝트 위치와 이름
    -import /samples/malware.exe \     # 임포트할 바이너리
    -postScript MyScript.py \          # 분석 후 실행할 스크립트
    -scriptPath /my_scripts \          # 스크립트 검색 경로
    -log /tmp/ghidra_analysis.log      # 로그 파일

# 디렉토리 전체 분석 (재귀)
./analyzeHeadless \
    /tmp/my_project BatchProject \
    -import /samples/ \                # 디렉토리 지정 시 하위 파일 전부
    -recursive \                       # 재귀 탐색
    -postScript ExtractStrings.py \
    -deleteProject                     # 분석 완료 후 프로젝트 삭제 (임시 분석)
# 기존 프로젝트에 스크립트만 실행 (재분석 없이)
./analyzeHeadless \
    /tmp/my_project ExistingProject \
    -process malware.exe \             # -import 대신 -process (이미 임포트된 파일)
    -noanalysis \                      # Auto Analysis 건너뜀 (이미 완료된 경우)
    -postScript MyQueryScript.py

# 스크립트에 인자 전달
./analyzeHeadless \
    /tmp/my_project MyProject \
    -import /samples/unknown.bin \
    -postScript HashExtractor.py "output.json" "True"

Headless 스크립트 예시 — 배치 문자열 추출

#@title Headless String Extractor
#@category Headless

"""
사용법:
analyzeHeadless [proj_dir] [proj_name] -import [dir] -recursive \
    -postScript ExtractStrings.py /output/results.txt
"""

import json
import os

args = getScriptArgs()
output_file = args[0] if args else "/tmp/strings_output.txt"

prog_name = currentProgram.getName()
results = {
    "binary": prog_name,
    "strings": [],
    "functions": [],
    "imports": []
}

# 정의된 문자열 수집
from ghidra.program.model.data import StringDataType

listing = currentProgram.getListing()
data_iter = listing.getDefinedData(True)

while data_iter.hasNext():
    d = data_iter.next()
    if isinstance(d.getDataType(), StringDataType):
        s = d.getValue()
        if s and len(str(s)) > 3:
            results["strings"].append({
                "addr": str(d.getAddress()),
                "value": str(s)
            })

# 임포트 목록 수집
ext_refs = currentProgram.getExternalManager()
ext_locs = ext_refs.getAllExternalLocations()
while ext_locs.hasNext():
    loc = ext_locs.next()
    results["imports"].append({
        "lib": loc.getLibraryName(),
        "func": loc.getLabel()
    })

# 결과를 파일에 append
with open(output_file, "a") as f:
    f.write(json.dumps(results) + "\n")

print(f"완료: {prog_name} → {output_file}")

완전한 자동 분석 파이프라인 구성

#!/bin/bash
# 악성코드 자동 분석 파이프라인

GHIDRA_HOME="/opt/ghidra"
SAMPLES_DIR="/samples/incoming"
OUTPUT_DIR="/analysis/results"
PROJECT_DIR="/tmp/ghidra_projects"
SCRIPTS_DIR="/my_scripts"

# 들어오는 샘플 처리
for sample in "$SAMPLES_DIR"/*.exe "$SAMPLES_DIR"/*.dll; do
    if [ ! -f "$sample" ]; then continue; fi
    
    basename=$(basename "$sample")
    proj_name="analysis_${basename%%.*}"
    output_json="$OUTPUT_DIR/${basename}.json"
    
    echo "[*] 분석 시작: $basename"
    
    # Ghidra Headless 실행
    "$GHIDRA_HOME/support/analyzeHeadless" \
        "$PROJECT_DIR" "$proj_name" \
        -import "$sample" \
        -scriptPath "$SCRIPTS_DIR" \
        -postScript ExtractStrings.py "$output_json" \
        -postScript APIUsageReport.py "$output_json" \
        -postScript SuspiciousFuncFinder.py "$output_json" \
        -deleteProject \
        -log "$OUTPUT_DIR/${basename}.log" \
        2>&1 | grep -v "^INFO"   # 너무 많은 INFO 로그 필터
    
    if [ $? -eq 0 ]; then
        echo "[+] 완료: $basename → $output_json"
    else
        echo "[-] 실패: $basename"
    fi
done

# 결과 집계
python3 aggregate_results.py "$OUTPUT_DIR"

Headless 분석 속도 최적화

-noanalysis 옵션으로 Auto Analysis를 끄면 임포트 속도가 10배 빨라진다. 스크립트가 특정 정보(문자열, 임포트 목록)만 필요하다면 Auto Analysis 없이도 얻을 수 있는 경우가 많다. 반대로 Decompiler 결과가 필요하다면 Analysis가 완료된 기존 프로젝트에서 -process로 스크립트만 실행하는 방법이 효율적이다.

BSim — 함수 유사도 검색

BSim(Binary Similarity)은 Ghidra 10.x부터 포함된 기능이다. 함수의 PCode를 분석해서 유사도 벡터를 생성하고, 이를 데이터베이스에 저장해 유사한 함수를 빠르게 찾는다. 악성코드 패밀리 분류, 재사용 코드 식별에 유용하다. 

# BSim 사용 개념 (CLI 방식)

# 1. BSim 서버 설정 (H2 DB 사용, 소규모)
./bsim createdatabase bsim_db H2

# 2. 바이너리를 BSim DB에 등록 (Headless로 대량 처리)
./analyzeHeadless /tmp/proj DB_Population \
    -import /samples/ -recursive \
    -postScript BSimAnalyzeHeadless.java bsim_db

# 3. 특정 바이너리에서 유사 함수 검색
# CodeBrowser에서: BSim → Search Functions Similar to All
# 유사도 90% 이상 함수 목록이 나옴

# 활용 시나리오:
# - 신규 악성코드 샘플이 들어왔을 때 BSim으로 기존 샘플과 비교
# - 유사도 높은 함수 발견 → 같은 패밀리 or 코드 재사용
# - 이전에 분석한 이름이 자동으로 적용됨
