왜 설치가 중요한가 — Java 버전 문제

Ghidra를 실행하다가 가장 먼저 막히는 곳이 Java 버전이다. Ghidra 10.x 이상은 Java 17 이상이 필요하다. Java 11로 시도하면 실행이 안 된다. 시스템에 자바가 여러 버전 설치된 경우 환경변수가 꼬여서 실행이 안 되는 경우도 있다. 이 섹션에서 이 부분을 완전히 해결한다.

Java JDK 설치

Adoptium에서 JDK 21 LTS를 받는 것을 권장한다. Oracle JDK도 되지만 라이선스 조건이 복잡하다.

# Winget으로 설치 (Windows 11 권장)
winget install EclipseAdoptium.Temurin.21.JDK

# 설치 확인
java -version
# openjdk version "21.0.x" ... 가 나와야 함

# JAVA_HOME 확인
echo %JAVA_HOME%

환경변수 JAVA_HOME이 JDK 21을 가리키고 있어야 한다. C:\Program Files\Eclipse Adoptium\jdk-21... 형태가 맞다. Path에도 %JAVA_HOME%\bin이 포함되어 있어야 한다. 

# Ubuntu/Debian
sudo apt update
sudo apt install openjdk-21-jdk

# 여러 자바 버전이 있을 때 선택
sudo update-alternatives --config java
# 21 버전 선택

# 확인
java -version

# JAVA_HOME 설정 (~/.bashrc 또는 ~/.zshrc)
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
export PATH=$JAVA_HOME/bin:$PATH
# Homebrew로 설치
brew install --cask temurin@21

# 확인
java -version

# ~/.zshrc에 추가
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
export PATH=$JAVA_HOME/bin:$PATH

Ghidra 다운로드 및 실행

# 1. 공식 다운로드 (항상 공식 사이트에서)
#    https://github.com/NationalSecurityAgency/ghidra/releases
#    또는 https://ghidra-sre.org/

# 2. 압축 해제
# Windows: ghidra_11.x_PUBLIC.zip 압축 풀기
# Linux/macOS:
unzip ghidra_11.x_PUBLIC.zip -d ~/tools/

# 3. 실행
# Windows:
ghidraRun.bat

# Linux/macOS:
./ghidraRun

# Java 경로를 명시하고 싶을 때:
JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 ./ghidraRun
⚠️
경로에 한글/공백 포함 금지

Ghidra 설치 경로에 한글이나 공백이 있으면 실행 오류가 날 수 있다. C:\ghidra 또는 /opt/ghidra처럼 ASCII 경로만 사용하자.

Ghidra 프로젝트 구조 이해

Ghidra를 처음 실행하면 Project Manager가 뜬다. 이게 당황스러운 이유는 "바이너리 파일 열기"처럼 직관적이지 않기 때문이다. Ghidra의 작업 단위는 프로젝트(Project)다.

비유를 들자면, 프로젝트는 분석 작업실이다. 이 안에 여러 바이너리를 넣어두고, 각각의 분석 결과(주석, 이름 변경, 구조체 정의 등)가 프로젝트에 저장된다. 같은 악성코드 패밀리의 샘플을 여러 개 분석한다면 하나의 프로젝트 안에 다 넣는 게 좋다. 

# 프로젝트 폴더 구조
my_analysis.rep/           # 프로젝트 데이터 디렉토리
├── data/
│   ├── idb/               # 바이너리별 분석 DB
│   └── versioned/         # 버전 추적 데이터
my_analysis.gpr            # 프로젝트 포인터 파일

Non-Shared vs Shared 프로젝트

혼자 분석할 때는 Non-Shared Project. 팀원과 같은 바이너리를 동시에 분석할 때는 Shared Project를 선택한다. Shared Project는 Ghidra Server를 별도로 설치해야 한다. 서버는 Ghidra 설치 경로의 server/ 폴더에 있다.

첫 바이너리 임포트 — 단계별 가이드

  • 1
    바이너리 임포트
    File → Import File 또는 바이너리를 Project 창에 드래그. Ghidra가 포맷을 자동 감지한다. 감지 결과가 나오면 확인한다. 
    # 자동 감지 결과 예시
Format: Portable Executable (PE) 32-bit
Language: x86:LE:32:default:windows
Compiler: windows
  • 2
    포맷이 틀렸을 때
    Raw 펌웨어나 인식 불가능한 포맷은 "Raw Binary"를 선택하고 언어(아키텍처)를 수동으로 지정한다. 나중에 Window → Memory Map에서 베이스 주소를 직접 잡아줘야 한다.
  • 3
    CodeBrowser에서 열기
    Project Manager에서 임포트된 파일을 더블클릭. 처음엔 "Auto Analyze?" 다이얼로그가 뜬다.
  • 4
    Auto Analysis 실행
    "Yes"를 클릭하면 분석기 목록이 나온다. 대부분의 경우 기본 선택을 그대로 두고 "Analyze"를 누르면 된다.

Auto Analysis — 어떤 분석기가 뭘 하나

Auto Analysis는 수십 개의 분석기를 순차/병렬로 실행한다. 전부 켜두면 좋을 것 같지만, 크기가 큰 바이너리에서는 시간이 오래 걸리거나 오분석이 생긴다. 중요한 것들만 이해해두자.

분석기하는 일권장
Disassemble Entry Points엔트리포인트에서 시작해 코드 경계 탐색필수
Function ID라이브러리 함수 시그니처 매칭 (libc, windows API 등)필수
Stack스택 변수 분석, 로컬 변수 타입 추론필수
Demangler (GNU/Microsoft)C++ 심볼 디맹글링필수 (C++ 바이너리)
Embedded MediaPE 리소스 섹션 분석선택
Aggressive Instruction Finder코드로 오인될 수 있는 영역까지 디스어셈블스트립 바이너리에서 유용, 오분석 위험
Windows x86 PE Exception HandlingSEH 핸들러 분석Windows PE 분석 시 유용
💡
나중에 다시 분석할 수 있다

Auto Analysis를 건너뛰거나 일부만 실행했어도 나중에 Analysis → Auto Analyze로 다시 실행할 수 있다. 특정 분석기만 선택해서 실행하는 것도 가능하다. "Analyze All Open"으로 프로젝트 내 모든 파일에 일괄 적용도 된다.

프로젝트 백업 권장

분석 도중 Ghidra가 크래시되면 작업이 날아갈 수 있다. File → Save를 습관화하고, 프로젝트 폴더 전체(.rep 폴더와 .gpr 파일)를 주기적으로 백업하자. Git으로 버전관리를 하는 분석가도 있다.

분석 준비 체크리스트

  • ✅ Java 17+ 설치 확인 (java -version)
  • ✅ JAVA_HOME 환경변수 설정
  • ✅ Ghidra 설치 경로에 한글/공백 없음
  • ✅ launch.properties에서 메모리 설정 확인
  • ✅ 프로젝트 생성 후 바이너리 임포트
  • ✅ Auto Analysis 완료 대기
