Data Type Manager 구조, 커스텀 struct/union/enum 정의, C 헤더 파일을 GDT로 변환, 구조체 적용으로 Decompiler 품질 향상, 실전 사례.

왜 데이터 타입이 중요한가

Ghidra가 바이너리를 처음 분석하면 대부분의 바이트는 "undefined"다. 바이트 덩어리가 정수인지, 포인터인지, 구조체인지 모르는 상태다. Ghidra가 추론할 수 있는 것은 코드(함수) 부분이고, 데이터 섹션의 복잡한 구조는 분석가가 직접 알려줘야 한다.

비유를 들면: 외국어 책을 펼쳤는데 알파벳은 읽히는데 단어의 의미를 모르는 상태다. 데이터 타입을 정의하는 건 사전을 만들어주는 작업이다. 사전이 생기면 전체 문장(함수)이 갑자기 읽힌다.

Data Type Manager 구조

Window → Data Type Manager 또는 Ctrl+D. 트리 구조로 되어 있다. 

Data Type Manager 트리 구조:

▼ Program (현재 분석 중인 바이너리)
  ├── BuiltInTypes      ← byte, dword, qword 등 기본 타입
  ├── /                 ← 사용자 정의 타입이 들어가는 곳
  └── IMPORTED          ← 임포트한 라이브러리 타입들

▼ BuiltInTypes         ← Ghidra 내장 타입 아카이브
▼ windows_vs12_32.gdt  ← Windows 32비트 PE 임포트 시 자동 로드
▼ ntddk_32.gdt         ← 커널 드라이버 분석용

GDT(Ghidra Data Type)는 타입 아카이브 파일이다. Ghidra 설치 디렉토리의 Ghidra/Features/Base/data/typeinfo/에 여러 GDT가 있다. POSIX, Windows API, C 표준 라이브러리 등의 타입이 미리 정의되어 있다.

구조체(struct) 정의하기

두 가지 방법이 있다. Listing에서 데이터를 선택하고 만드는 방법과, Data Type Manager에서 처음부터 만드는 방법.

이미 데이터가 있는 주소에서 구조체 레이아웃을 직접 정의하는 방법. 가장 직관적이다.

  • 1
    데이터 영역에서 구조체가 시작하는 주소로 이동
    해당 바이트들이 어떤 구조인지 Decompiler로 추정해두기
  • 2
    Listing에서 구조체 범위만큼 드래그로 선택
    Data → Create Structure 클릭
  • 3
    Structure Editor가 열린다. 각 필드의 이름과 타입을 지정
    OK를 누르면 해당 주소의 데이터가 구조체로 해석된다

처음부터 구조체 레이아웃을 설계할 때. 코드 분석으로 구조를 파악했을 때 사용한다.

/* 분석 중 Decompiler에서 이런 패턴을 발견했다고 하자: */
int iVar1 = *(param_1);             // offset 0: int
char *pcVar2 = *(param_1 + 4);     // offset 4: char*
int iVar3 = *(param_1 + 8);       // offset 8: int
byte bVar4 = *(param_1 + 12);     // offset 12: byte

/* → 이를 바탕으로 구조체 정의:
   Data Type Manager → Program 우클릭 → New → Structure */

struct UserRecord {
    int    id;          // offset 0, size 4
    char  *username;    // offset 4, size 4 (32bit) or 8 (64bit)
    int    role;        // offset 8, size 4
    byte   is_admin;   // offset 12, size 1
};  // total: 13 bytes (패딩 고려 시 16)

Windows API 구조체처럼 C 헤더가 이미 있을 때. 수백 개의 구조체를 한 번에 임포트할 수 있다.

# 방법 1: Ghidra 내장 Parse C Header 기능
# File → Parse C Source
# C 헤더 파일을 지정하면 GDT로 자동 변환

# 예: 사용자 정의 구조체 헤더 파일 (my_structs.h)
/*
typedef struct {
    int    user_id;
    char   username[32];
    int    access_level;
    time_t last_login;
} UserRecord;

typedef struct {

# 주의: Parse C Source는 간단한 헤더에만 잘 동작한다
# 복잡한 매크로나 컴파일러 의존 코드는 전처리가 필요

구조체를 코드에 적용하기

구조체를 정의했으면 Decompiler에 적용해야 Decompiler 결과가 바뀐다. 변수에 커서를 놓고 T를 누르거나, 우클릭 → "Retype Variable"을 선택한다. 

/* 적용 전: 구조체가 undefined4 덩어리로 보임 */
void process_user(undefined4 *param_1)
{
    if (*(param_1 + 3) != 0) {     // is_admin 체크인데 알 수 없음
        FUN_00401500(param_1);
    }
    log_action(*(param_1 + 1));    // username 포인터인데 알 수 없음
}

/* 적용 후: UserRecord* 타입을 param_1에 적용 */
void process_user(UserRecord *user)
{
    if (user->is_admin != 0) {      // 의미가 명확해짐
        grant_admin_access(user);
    }
    log_action(user->username);     // 필드 이름으로 표시
}
⚠️
패딩(Padding) 주의

컴파일러는 구조체 필드를 정렬(alignment) 규칙에 따라 패딩을 삽입한다. char 다음에 int가 오면 3바이트 패딩이 생기는 식이다. Ghidra Structure Editor에서 "Pack Structure" 옵션을 언제 켜고 끌지 실제 바이너리 동작과 비교하면서 맞춰야 한다.

Union 정의

Union은 같은 메모리 위치를 여러 타입으로 해석하는 구조다. 네트워크 패킷 파싱, 레지스터 뷰 등에서 자주 쓰인다. 

/* Union 예시: 4바이트를 다양하게 해석 */
union PacketData {
    uint32_t  raw;          // 32비트 정수로
    struct {
        uint8_t  type;       // 하위 1바이트: 패킷 타입
        uint8_t  flags;      // 다음 1바이트: 플래그
        uint16_t length;     // 상위 2바이트: 길이
    } fields;
    uint8_t   bytes[4];      // 바이트 배열로
};

Enum 정의 — 매직 넘버 해석

바이너리 분석에서 if (eax == 3) 같은 코드를 만나면 "3이 무슨 의미인가?"가 항상 문제다. Enum을 정의하면 if (status == ERROR_FILE_NOT_FOUND)처럼 표시된다. 

/* Data Type Manager → New → Enum */
enum ErrorCode : uint32_t {
    SUCCESS          = 0x00000000,
    ERROR_INVALID    = 0x00000001,
    ERROR_AUTH_FAIL  = 0x00000002,
    ERROR_NOT_FOUND  = 0x00000003,
    ERROR_TIMEOUT    = 0x00000004
};

Enum을 정의한 후, Listing에서 해당 상수 값에 커서를 놓고 Equates → Set Equate로 Enum을 연결하면 숫자 대신 이름이 표시된다.

실전 사례 — Windows 악성코드 구조체 적용

실제 악성코드 분석에서 Windows 구조체를 어떻게 활용하는지 보자. CreateThread를 사용하는 악성코드라면 LPTHREAD_START_ROUTINE 함수 포인터를 알아야 한다. 

/* windows_vs12_32.gdt가 로드된 경우 이미 정의되어 있는 구조체들: */

/* STARTUPINFOA 구조체 적용 예시 */
/* 자동 추론 결과: */
CreateProcessA(
    0, "cmd.exe", 0, 0, 0,
    0, 0,
    local_50,          // ← STARTUPINFOA* 인데 undefined로 표시
    local_10           // ← PROCESS_INFORMATION* 인데 undefined로 표시
);

/* STARTUPINFOA 타입 적용 후: */
CreateProcessA(
    0, "cmd.exe", 0, 0, FALSE,
    CREATE_NO_WINDOW,
    0,
    &startupInfo,      // STARTUPINFOA 구조체 → 필드별로 분석 가능
    &procInfo          // PROCESS_INFORMATION → hProcess, hThread 등 접근 가능
);

배열(Array) 정의

데이터 섹션에 구조체 배열이 있을 때. 시작 주소에서 우클릭 → "Create Array"로 만들거나, Structure 안에 배열 필드를 정의한다. 

/* Structure Editor에서 배열 필드 정의 */
struct Config {
    char  name[64];       // 64바이트 char 배열
    int   ports[8];       // 8개 int 배열 (C2 서버 포트 목록)
    byte  flags[4];       // 4바이트 플래그 배열
};

/* Listing에서 배열 전체에 구조체 적용하기:
   시작 주소 선택 → 배열 끝까지 드래그 → Data → Create Structure Array */

함수 시그니처 타입 정의 (Function Typedef)

악성코드에서 함수 포인터를 통해 간접 호출(CALL [EAX])이 많이 나온다. 함수 typedef를 정의하면 Decompiler가 올바른 시그니처로 함수를 표시한다. 

/* Data Type Manager → New → Function Definition */

/* 예: API 해시 해석 함수의 시그니처 */
typedef int (*PFUNC_HASH_RESOLVE)(uint32_t hash, void **out_func);

/* 적용: 함수 포인터 변수에 이 타입을 지정 */
/* 이후 CALL 명령에서 올바른 파라미터 타입이 표시됨 */

GDT 파일 내보내기 & 재사용

힘들게 정의한 구조체들을 GDT 파일로 내보내면 다른 프로젝트에서 재사용할 수 있다. Data Type Manager에서 내보내고 싶은 아카이브를 우클릭 → "Export". 같은 바이너리 패밀리를 분석할 때 특히 유용하다.

Version Tracking — 업데이트된 바이너리 비교

악성코드나 소프트웨어의 새 버전이 나왔을 때, 이전 버전에서 분석한 이름/구조체를 새 버전에 자동으로 적용하는 기능이다. 패치 분석, 악성코드 업데이트 추적에 유용하다. 

# Version Tracking 사용법
# 1. Tools → Version Tracking (두 개의 프로그램 필요)
# 2. "Source" (이전 버전, 분석 완료) 와 "Destination" (새 버전) 지정
# 3. 자동 매칭 실행: 함수 해시, 심볼 이름, 구조 유사도 비교
# 4. 매칭 결과 검토 후 Accept → 이전 분석 결과가 새 버전에 복사됨
