스크립팅이 필요한 순간

Ghidra GUI로 분석하다 보면 반복 작업이 생긴다. "FUN_"으로 시작하는 함수 100개의 이름을 각각 클릭해서 바꾸는 작업, 특정 API 호출 패턴을 모두 찾아서 주석 달기, 암호화된 문자열을 모두 찾아서 복호화 결과를 주석으로 달기. 이런 작업은 스크립트 없이는 불가능하거나 비현실적이다.

Ghidra 스크립팅은 두 언어를 지원한다. Java는 Ghidra의 native 언어라 API 접근이 완전하고 빠르다. Jython(Python 2.7)은 문법이 익숙해서 빠르게 프로토타이핑하기 좋다. Ghidra 11.x에서 Python 3(PyGhidra)도 사용할 수 있지만 아직 설정이 복잡하다. 이 챕터는 Jython을 기준으로 한다.

  • 3
    새 스크립트: 우측 상단 "New Script" 버튼 → Python 선택 → 스크립트 이름 지정.
    스크립트 파일은 ~/.ghidra/.ghidra_[version]/Extensions/에 저장된다.
  • 4
    Script Editor(내장 에디터)에서 작성하거나, VS Code 같은 외부 에디터로 작성 후 Script Manager에서 새로고침.

실전 스크립트 ③: 암호화된 문자열 복호화 자동 주석

악성코드에서 문자열을 XOR로 암호화해두는 경우가 많다. 모든 암호화 문자열을 찾아 복호화하고 주석으로 달아준다. 

#@title XOR String Decryptor
#@category Malware Analysis

def xor_decrypt(data, key):
    """단일 바이트 XOR 복호화"""
    return "".join(chr(b ^ key) for b in data if b ^ key != 0)

def is_printable(s):
    return all(32 <= ord(c) < 127 for c in s)

XOR_KEY = 0x37     # 실제 분석에서 파악한 키
MIN_LEN  = 4       # 최소 문자열 길이

# 데이터 섹션 스캔
mem = currentProgram.getMemory()
listing = currentProgram.getListing()

for block in mem.getBlocks():
    if block.isInitialized() and not block.isExecute():
        addr = block.getStart()
        end  = block.getEnd()
        
        while addr.compareTo(end) < 0:
            # 연속된 비-null 바이트 추출
            raw_bytes = []
            cur = addr
            while cur.compareTo(end) < 0:
                b = mem.getByte(cur) & 0xFF
                if b == 0:
                    break
                raw_bytes.append(b)
                cur = cur.add(1)
            
            if len(raw_bytes) >= MIN_LEN:
                decrypted = xor_decrypt(raw_bytes, XOR_KEY)
                if len(decrypted) >= MIN_LEN and is_printable(decrypted):
                    cu = listing.getCodeUnitAt(addr)
                    if cu:
                        cu.setComment(cu.EOL_COMMENT, f'Decrypted: "{decrypted}"')
                        print(f"[{addr}] {decrypted}")
            
            addr = cur.add(1)

실전 스크립트 ④: API 해시 해석

EMOTET, TrickBot 같은 악성코드는 API 이름 대신 해시값으로 함수를 동적으로 불러온다. 미리 해시 DB를 만들어두고 Ghidra에서 자동으로 이름을 달아준다. 

#@title API Hash Resolver
#@category Malware Analysis

import json

# 사전에 계산해둔 해시 → API 이름 매핑
# (실제 사용 시 더 큰 DB 사용)
HASH_DB = {
    0x7C0DFCAA: "LoadLibraryA",
    0xEC0E4E8E: "GetProcAddress",
    0x3F9287AE: "VirtualAlloc",
    0x74D9A8AB: "CreateThread",
    0xE8AFE98:  "WinExec",
}

# resolve_api 함수를 찾아서 인자 분석
fm = currentProgram.getFunctionManager()
resolve_func = fm.getFunctions("resolve_api", True)

for func in resolve_func:
    refs = currentProgram.getReferenceManager()\
                         .getReferencesTo(func.getEntryPoint())
    
    for ref in refs:
        call_addr = ref.getFromAddress()
        listing = currentProgram.getListing()
        
        # CALL 명령어 바로 전 PUSH 명령어 확인 (해시값 추출)
        instr = listing.getInstructionBefore(call_addr)
        if instr and instr.getMnemonicString() == "PUSH":
            operand = instr.getOperandValues(0)
            if operand:
                hash_val = operand[0].intValue() & 0xFFFFFFFF
                api_name = HASH_DB.get(hash_val)
                
                if api_name:
                    cu = listing.getCodeUnitAt(call_addr)
                    cu.setComment(cu.EOL_COMMENT, f"→ {api_name}")
                    print(f"[{call_addr}] Hash 0x{hash_val:08X} = {api_name}")

실전 스크립트 ⑤: 함수 크기 기준 분류

줄 수가 많은 함수 Top 20을 뽑아서 분석 우선순위를 정한다. 복잡한 함수일수록 핵심 로직일 가능성이 높다. 

#@title Find Complex Functions (by size)
#@category Analysis

functions = list(currentProgram.getFunctionManager().getFunctions(True))

# 함수 크기 기준 정렬
sized = [(f.getBody().getNumAddresses(), f) for f in functions]
sized.sort(key=lambda x: x[0], reverse=True)

print("=== 가장 큰 함수 Top 20 ===")
for i, (size, func) in enumerate(sized[:20]):
    print(f"{i+1:2d}. [{func.getEntryPoint()}] {func.getName():<40s} {size:6d} bytes")

print("\n=== 분석 우선순위 추천 ===")
for size, func in sized[:5]:
    # Plate comment로 표시
    func.setComment(f"[분석 필요] 크기: {size} bytes - 핵심 함수 후보")

Transaction — 스크립트에서 DB 수정하기

스크립트에서 이름 변경, 주석 추가, 구조체 적용 등 Ghidra DB를 수정할 때는 반드시 Transaction 안에서 해야 한다. 그렇지 않으면 Undo가 되지 않고, 경우에 따라 오류가 발생한다. 

# Transaction 패턴
from ghidra.program.database import ProgramDB

tid = currentProgram.startTransaction("My Script Changes")
try:
    # DB 수정 작업
    func = getFunctionAt(toAddr(0x401234))
    func.setName("my_renamed_func", ghidra.program.model.symbol.SourceType.USER_DEFINED)
    
    # 주석 추가
    cu = currentProgram.getListing().getCodeUnitAt(toAddr(0x401234))
    cu.setComment(cu.PLATE_COMMENT, "분석 완료 - 비밀번호 검증 함수")
    
    currentProgram.endTransaction(tid, True)  # True = commit
except Exception as e:
    currentProgram.endTransaction(tid, False) # False = rollback
    print(f"오류: {e}")
⚠️
Jython은 Python 2.7

Jython 환경은 Python 2.7이다. print()가 아니라 print 문법을 쓰는 오래된 예제가 많다. from __future__ import print_function을 추가하면 Python 3 문법과 호환된다. Python 3 라이브러리(requests, scapy 등)는 Jython에서 사용할 수 없다.
