실행 시작 명령어

run (r)

프로그램을 처음부터 실행. 브레이크포인트 전까지 달린다. 인자는 run arg1 arg2.

starti

첫 번째 어셈블리 명령어에서 즉시 멈춤. 프로그램 시작을 한 스텝씩 보고 싶을 때.

start

main() 진입점에 임시 BP를 걸고 실행. libc 초기화 코드를 건너뛰고 main부터 보고 싶을 때.

# 인자 전달 방법들
pwndbg> run arg1 arg2
pwndbg> run < input.txt             # stdin 리다이렉션
pwndbg> run $(python3 -c "print('A'*100)")  # 인라인 페이로드

# 환경변수 제어
pwndbg> set environment MYVAR=value
pwndbg> unset environment MYVAR

# 재시작 (인자 유지)
pwndbg> run                         # 이전 인자 그대로 재시작

실행 이동 명령어

명령어약어동작주의
steps소스 한 줄 실행. 함수 내부로 들어감debug symbol 필요
stepisi어셈블리 명령어 하나 실행. 함수 내부로 들어감가장 자세한 제어
nextn소스 한 줄. 함수 호출은 건너뜀debug symbol 필요
nextini어셈블리 명령어 하나. CALL은 건너뜀익스플로잇에서 주로 사용
continuec다음 브레이크포인트까지 실행
finishfin현재 함수 끝까지 실행 후 반환깊이 들어간 함수에서 탈출
untilu지정 주소 또는 줄까지 실행until *0x401234
jumpjPC를 강제로 지정 주소로 이동스택 상태는 변하지 않음
# 실전 패턴: 함수 호출 분석
pwndbg> ni       # CALL 명령어까지 이동
pwndbg> si       # 함수 내부로 진입
... 내부 분석 ...
pwndbg> finish   # 함수 끝으로 나와서 반환값 확인

# 여러 번 실행
pwndbg> si 5     # si를 5번 실행
pwndbg> ni 10    # ni를 10번 실행

소프트웨어 브레이크포인트

# 기본 브레이크포인트
pwndbg> break main           # 함수 이름으로
pwndbg> break *0x401234      # 절대 주소로 (*는 주소임을 명시)
pwndbg> break *main+48       # 함수 + 오프셋
pwndbg> b *0x401234          # break 약어

# 임시 브레이크포인트 (한 번 히트 후 자동 삭제)
pwndbg> tbreak *0x401234

# 브레이크포인트 목록
pwndbg> info breakpoints
pwndbg> i b                  # 약어

# 브레이크포인트 삭제/비활성화
pwndbg> delete 1             # 번호로 삭제
pwndbg> delete               # 전체 삭제
pwndbg> disable 2            # 비활성화 (삭제 아님)
pwndbg> enable 2             # 재활성화

조건부 브레이크포인트

특정 조건이 맞을 때만 멈추는 브레이크포인트다. 루프 안에서 특정 인덱스에서만 멈추거나, 레지스터 값이 특정 값일 때만 멈출 수 있다. 

# 조건 달기
pwndbg> break *0x401234 if $rdi == 0x42
pwndbg> break *main+100  if $rax > 0

# 기존 BP에 조건 추가
pwndbg> condition 1 $rcx == 0   # 브레이크포인트 1번에 조건
pwndbg> condition 1              # 조건 제거

# 횟수 조건 (N번째 히트 때 멈춤)
pwndbg> break *0x401234
pwndbg> ignore 1 9              # 9번 무시하고 10번째에 멈춤

# 실전 예시: malloc이 특정 크기를 요청할 때만 멈춤
pwndbg> break malloc if $rdi == 0x40

하드웨어 브레이크포인트

소프트웨어 BP는 코드에 0xCC(INT3) 바이트를 삽입한다. 자기 수정 코드, 언패커, 안티디버깅 코드는 이를 감지한다. 하드웨어 BP는 CPU 레지스터(DR0~DR3)를 사용하므로 메모리를 수정하지 않는다. 단, 개수가 4개로 제한된다. 

# 하드웨어 브레이크포인트
pwndbg> hbreak *0x401234    # 실행 위치 하드웨어 BP

# 와치포인트 (메모리 값 변경 감지)
pwndbg> watch *0x404040     # 0x404040의 값이 바뀔 때 멈춤
pwndbg> rwatch *0x404040    # 읽을 때 멈춤
pwndbg> awatch *0x404040    # 읽거나 쓸 때 멈춤

# 실전: 전역 변수 값이 언제 바뀌는지 추적
pwndbg> watch *(int*)0x404020  # int 크기로
pwndbg> watch -l target_var    # 심볼 이름으로 (debug symbol 필요)

catch syscall — 시스템 콜 감지

# 특정 시스템 콜에서 멈춤
pwndbg> catch syscall read       # read() 시스템 콜
pwndbg> catch syscall write      # write() 시스템 콜
pwndbg> catch syscall execve     # execve() — 셸 실행 직전!
pwndbg> catch syscall open openat  # 여러 개
pwndbg> catch syscall            # 모든 시스템 콜

# 시스템 콜 번호로 지정 (x86_64 기준)
pwndbg> catch syscall 0          # 0 = read
pwndbg> catch syscall 59         # 59 = execve

# 실전: 셸코드가 execve를 호출하는 순간 잡기
pwndbg> catch syscall execve
pwndbg> run < payload
# execve("/bin/sh", ...) 호출 직전에 멈춤
# 이때 RDI = "/bin/sh" 문자열 주소 확인 가능

브레이크포인트 명령 자동화 — commands

브레이크포인트에 히트할 때마다 자동으로 실행할 GDB 명령어를 등록할 수 있다. 반복적인 분석을 자동화하는 데 유용하다. 

# BP 1번에 명령어 등록
pwndbg> commands 1
Type commands for breakpoint(s) 1, one per line.
End with a line saying just "end".
> print $rdi
> x/s $rdi
> continue
> end

# → 이 BP에 걸릴 때마다 RDI 값을 출력하고 자동으로 계속 실행

# 실전: malloc 호출마다 크기 로깅
pwndbg> break malloc
pwndbg> commands
> printf "malloc(%ld)\n", $rdi
> continue
> end

procinfo — 프로세스 상태 한눈에

pwndbg> procinfo

$rebase — PIE 바이너리에서 주소 계산

PIE(Position Independent Executable) 바이너리는 매번 베이스 주소가 달라진다. pwndbg는 $rebase라는 편의 함수를 제공한다. break *$rebase(0x1234)는 "바이너리 베이스 + 0x1234"로 BP를 건다. Ghidra에서 확인한 오프셋을 그대로 쓸 수 있다.
