vanilla GDB — 왜 쓰기 힘든가

GDB는 강력하다. 하지만 UI가 1990년대에 멈춰 있다. 브레이크포인트에서 멈추면 현재 레지스터가 뭔지, 스택이 어떤 상태인지, 다음 명령어가 뭔지 알려면 각각 별도 명령어를 쳐야 한다. 익스플로잇을 개발하면서 x/30gx $rsp 같은 명령어를 매번 입력하는 건 지루하고 실수가 잦다.

pwndbg가 해결하는 것은 간단하다. 매번 물어봐야 했던 정보를 멈출 때마다 자동으로 출력한다. 레지스터, 다음 몇 개의 어셈블리 명령어, 스택 내용, 콜 스택이 한 화면에 정렬된다. 이것만으로도 분석 속도가 2~3배 빨라진다.

선택 기준

CTF, 리눅스 바이너리 익스플로잇, pwntools와 함께 쓴다면 pwndbg. macOS에서 네이티브 디버깅이 필요하다면 pwndbg + LLDB. 이미 GEF에 익숙하고 갈아탈 이유가 없다면 그대로 써도 된다.

설치

# 방법 1: setup.sh (권장 — 의존성 자동 처리)
git clone https://github.com/pwndbg/pwndbg
cd pwndbg
./setup.sh

# 설치 확인
gdb --version    # GDB 12.1 이상 필요
gdb -q           # 실행 시 pwndbg> 프롬프트가 뜨면 성공

# 방법 2: pip (Python 환경에 설치)
pip install pwndbg
# 이후 ~/.gdbinit에 자동으로 추가됨
⚠️
Ubuntu 20.04는 지원 종료

Ubuntu 20.04는 2024.08.29 릴리스까지만 공식 지원. 최신 기능을 쓰려면 22.04 이상으로 업그레이드하거나 Docker를 쓰자.

# GitHub Releases에서 포터블 tar.xz 다운로드
# https://github.com/pwndbg/pwndbg/releases

# x86_64 GDB 버전
wget https://github.com/pwndbg/pwndbg/releases/download/2025.04.18/\
pwndbg_2025.04.18_amd64.tar.xz

tar xf pwndbg_2025.04.18_amd64.tar.xz
cd pwndbg_2025.04.18_amd64/

# 포터블 버전은 시스템 GDB 없이도 실행 가능
./gdb.sh ./target_binary

# ARM64 (Apple Silicon 포함 원격 디버깅용)
# pwndbg_2025.04.18_arm64.tar.xz 다운로드 후 동일하게

포터블 버전은 GDB가 설치되지 않은 환경이나 여러 버전을 함께 써야 할 때 유용하다. CTF 서버에서 직접 다운받아 쓰는 패턴에도 적합하다.

# macOS는 GDB가 아니라 LLDB 경유
# Homebrew로 pwndbg 설치
brew install pwndbg

# LLDB 버전 실행
pwndbg-lldb ./target_binary

# 또는 원격 GDB 디버깅 (Rosetta 환경)
# gdb-multiarch + pwndbg로 원격 연결 가능
pwndbg-gdb -q
pwndbg> target remote :1337

macOS에서 LLDB 기반 pwndbg는 2025.01 릴리스부터 공식 지원. Intel과 Apple Silicon 모두 지원하며 Mach-O 바이너리도 분석 가능하다.

# CTF/익스플로잇 개발에 특화된 Docker 이미지
docker pull pwndbg/pwndbg:latest

# 로컬 바이너리 마운트해서 실행
docker run --rm -it \
  -v $(pwd):/pwn \
  --cap-add=SYS_PTRACE \
  pwndbg/pwndbg \
  gdb /pwn/target_binary

# docker-compose (pwntools까지 함께)
# 별도 CTF 환경 이미지 사용 추천:
# io.netgarage.org, ctf-repo 등

~/.gdbinit 구성

pwndbg 설치 시 ~/.gdbinit에 로드 줄이 자동으로 추가된다. 여기에 자주 쓰는 설정을 추가해두면 매번 입력할 필요가 없다. 

# ~/.gdbinit 예시

# pwndbg 로드 (자동 추가됨)
source ~/pwndbg/gdbinit.py

# ASLR 끄기 (로컬 디버깅 시 편의)
set disable-randomization on

# Intel 문법 (AT&T 싫다면)
set disassembly-flavor intel

# 자동으로 소스 코드 보기 (컴파일 시 -g 옵션 사용 시)
set print pretty on

# 히스토리 저장
set history save on
set history filename ~/.gdb_history
set history size 10000

# 브레이크포인트 도달 시 context 자동 출력 (기본값이지만 명시)
set context-output stdout

# 컨텍스트 표시 섹션 순서 지정
pwndbg> set context-sections regs disasm stack backtrace

pwndbg 설정 커스터마이징

# pwndbg 내부에서 설정 확인
pwndbg> config           # 전체 설정 목록
pwndbg> config context   # context 관련 설정만

# 자주 쓰는 설정 변경
pwndbg> set context-sections regs disasm code stack backtrace
pwndbg> set show-compact-regs on    # 레지스터 컴팩트하게
pwndbg> set dereference-limit 5     # telescope 역참조 깊이
pwndbg> set hexdump-width 16        # hexdump 너비

# 테마 변경 (pwndbg-themes 저장소 참고)
# https://github.com/pwndbg/pwndbg-themes

pwndbg 내장 도움말

# pwndbg 전용 명령어 목록
pwndbg> pwndbg           # 전체 pwndbg 명령어 나열
pwndbg> pwndbg heap      # "heap" 포함된 명령어만
pwndbg> help telescope   # 특정 명령어 상세 도움말

# GDB 기본 명령어도 여전히 작동
pwndbg> help x           # examine 명령어 도움말
pwndbg> help break       # breakpoint 도움말

첫 실행 — 바이너리 로드

# 바이너리와 함께 시작
gdb ./target

# 실행 중인 프로세스 attach
gdb -p 1234              # PID로
gdb ./target             # 이후: attach 1234

# 인자와 함께
gdb --args ./target arg1 arg2

# core dump 분석
gdb ./target core.1234

# 원격 gdbserver 연결
# 대상 서버: gdbserver 0.0.0.0:1337 ./target
gdb -q
pwndbg> target remote 192.168.1.100:1337
