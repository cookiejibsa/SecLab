LEGEND — 색상이 의미하는 것

Context 화면 맨 위의 LEGEND 줄이 색상 코드를 알려준다. 주소나 값에 색이 입혀져 있으면 그 주소가 어느 메모리 영역에 속하는지 바로 알 수 있다.

색상의미예시
🟦 파란색 계열STACK 영역0x7fffffffe288 — 스택 주소
🟩 초록색 계열HEAP 영역0x555555559260 — malloc() 반환 주소
🟥 빨간색 계열CODE 영역 (실행 가능)0x401234 — 텍스트 섹션
🟨 노란색 계열DATA 영역0x404040 — .data/.bss
🟪 자홍색 계열RWX 영역 (읽기+쓰기+실행)JIT 코드, 셸코드 영역
흰색/회색RODATA / 기타0x402000 — 읽기 전용 데이터

REGISTERS 패널 읽기

레지스터 값 옆에 —▸나 ◂— 화살표가 보이면 그 값이 포인터라는 뜻이다. pwndbg가 자동으로 역참조(dereference)해서 가리키는 곳의 내용을 보여준다. 

# 레지스터 읽기 예시
pwndbg> RDI  0x7ffff7a3b3d7  ◂— "Enter password: "
#       ^주소              ^이 주소를 역참조한 값 (문자열)

pwndbg> RSP  0x7fffffffe288  —▸ 0x401234 (main+48)
#       ^스택 포인터         ^RSP가 가리키는 곳 → 리턴 주소

pwndbg> RBP  0x7fffffffe2b0  —▸ 0x7fffffffe2d0 ◂— 0x0
#       ^프레임 포인터        ^RBP가 가리키는 곳 → 이전 RBP

변경된 레지스터는 색상이 달라진다. 이전 멈춤에서 바뀐 값은 즉시 눈에 띄어서 어떤 명령어가 무엇을 바꿨는지 추적하기 쉽다.

DISASM 패널 — Unicorn 에뮬레이션의 비밀

pwndbg의 DISASM 패널은 단순히 현재 PC 주변 명령어를 나열하지 않는다. Unicorn Engine으로 다음 몇 개의 명령어를 미리 에뮬레이션해서, 실제로 실행될 명령어만 표시한다.

이게 중요한 이유는 조건 분기 때문이다. JZ 명령어 앞에서 멈췄을 때, Zero Flag 상태를 확인해서 "이 분기가 실제로 점프할지"를 미리 계산하고 화살표로 알려준다. 점프 테이블, PLT 항목, ROP 체인을 단계별로 실행할 때도 실제 실행 경로만 보여준다. 

; DISASM 패널에서 분기 예측 표시 예시
; ► 는 현재 실행 위치, 화살표 방향이 점프 방향

 ► 0x401210    test   eax, eax
   0x401212    je     0x40123a        <-- 이 분기는 취해짐 (ZF=1)
                                         ↓ 점프한다면:
   0x40123a    mov    edi, 0x1
   0x40123f    call   0x401090 <exit@plt>

STACK 패널 — 스택 telescope

STACK 패널은 RSP 기준으로 위쪽 스택 항목들을 보여준다. 각 줄에 오프셋, 주소, 역참조 체인이 나온다. 

# STACK 패널 읽기
00:0000│ rsp  0x7fffffffe288 —▸ 0x401234 (main+48)
#  ^오프셋 ^레지스터 표시   ^스택 주소      ^스택에 저장된 값 (리턴 주소)

01:0008│      0x7fffffffe290 ◂— 'AAAAAAAA'
#  ^8바이트 위   ^주소          ^내용이 문자열처럼 보임 (공격 패턴 감지)

02:0010│ rbp  0x7fffffffe298 —▸ 0x7fffffffe2b0 ◂— 0x0
#  ^RBP 위치    ^주소          ^이전 RBP 저장 위치

00:0000에서 숫자는 RSP로부터의 오프셋이다. │ rsp는 현재 레지스터가 이 위치를 가리킨다는 표시. 버퍼 오버플로로 스택이 덮일 때 이 패널에서 즉시 확인된다.

BACKTRACE 패널

콜 스택을 보여준다. f 0이 현재 함수, f 1이 호출자, 이런 식으로 올라간다. 중첩된 함수 안에서 길을 잃었을 때 유용하다. 

# BACKTRACE 예시 — nested call 상황
 ► f 0  0x7ffff7a3b151  __GI___libc_read+17
   f 1  0x401257         read_input+35
   f 2  0x401189         main+57
   f 3  0x7ffff7a3d0b3  __libc_start_main+243

# 특정 프레임으로 이동
pwndbg> frame 2          # main 프레임으로
pwndbg> bt               # 전체 backtrace 출력 (GDB 내장)
pwndbg> backtrace full   # 지역 변수까지 포함

context 명령어 — 수동 재출력 & 섹션 제어

# 화면이 흐트러졌을 때 재출력
pwndbg> context

# 특정 섹션만 출력
pwndbg> context regs
pwndbg> context disasm
pwndbg> context stack
pwndbg> context backtrace
pwndbg> context code        # 소스 코드 (debug symbol 있을 때)

# 여러 섹션 함께
pwndbg> context regs disasm stack

# 특정 섹션 토글 (임시 끄기/켜기)
pwndbg> context disasm --off    # DISASM 패널 끄기
pwndbg> context disasm --on     # 다시 켜기

# 기본 표시 섹션 순서 변경 (.gdbinit에서 설정 가능)
pwndbg> set context-sections regs disasm stack backtrace

context history — 이전 상태 비교

pwndbg 2025.01+에서 추가된 기능이다. 이전 멈춤의 context 출력을 다시 볼 수 있다. 

# context history 보기 (2025.01+ 기능)
pwndbg> context-history     # 이전 context 출력 목록
pwndbg> context-history 3   # 3번 이전 context 보기
💡
TUI 모드로 항상 context 유지하기

GDB의 TUI(Text User Interface) 모드에서 pwndbg를 쓰면 context가 터미널 상단에 고정된다. tui layout pwndbg를 입력하면 된다. tmux와 함께 쓰면 context를 다른 패인에 분리할 수도 있다 (jcfg의 split-context 블로그 참고).
