Chapter 05 · Part 2 — 핵심 명령어

스택 & 레지스터 분석

레지스터와 스택을 읽고 쓰는 법 — 익스플로잇의 기초 중의 기초

레지스터 읽기

# 전체 레지스터 출력
pwndbg> regs             # pwndbg 스타일 (색상, 역참조 포함)
pwndbg> info registers   # GDB 기본 방식
pwndbg> i r              # 약어
pwndbg> i r rax rdi rsi  # 특정 레지스터만

# 개별 레지스터 출력 (print)
pwndbg> p $rax           # RAX 값 출력
pwndbg> p $rsp           # RSP 출력
pwndbg> p/x $rax         # 16진수로
pwndbg> p/d $rax         # 10진수로
pwndbg> p/t $rax         # 2진수로 (플래그 분석 시)

# 레지스터로 계산
pwndbg> p $rbp - $rsp    # 스택 프레임 크기
pwndbg> p $rdi + 0x8     # 오프셋 계산
pwndbg> p (void*)$rax    # 포인터로 캐스팅

레지스터 쓰기 — 값 강제 변경

# 레지스터 값 변경
pwndbg> set $rax = 0x1          # RAX를 1로
pwndbg> set $rdi = 0x404040     # 함수 인자 변조
pwndbg> set $rip = 0x401234     # 실행 흐름 강제 변경

# 실전: 조건 분기 강제 변경
# JNZ가 나왔을 때 점프 안 하게 하려면:
pwndbg> set $eflags = $eflags | 0x40    # ZF 세트 (JZ/JE 조건 충족)
pwndbg> set $eflags = $eflags & ~0x40   # ZF 클리어

# 더 간단하게: jump로 분기 강제
pwndbg> jump *0x401250          # 조건 무시하고 이 주소로 점프

메모리 값 변경

# set을 이용한 메모리 패치
pwndbg> set *(int*)0x404040 = 0x1337
pwndbg> set *(long*)$rsp = 0x401234    # 스택 위 값 변경
pwndbg> set *(char*)0x402000 = 0x90   # NOP 삽입

# 배열로 여러 바이트 변경
pwndbg> set {char[4]}0x402000 = {0x90, 0x90, 0x90, 0xC3}
# NOP NOP NOP RET 패치

stack 명령어

# pwndbg의 stack 명령어 (telescope의 스택 특화 버전)
pwndbg> stack            # RSP 기준 기본 8개
pwndbg> stack 20         # 20개 항목
pwndbg> stack -i         # 역순 (높은 주소가 위, 스택 시각화)

# 스택 분석 예시 — 함수 호출 직후
pwndbg> stack 10
# 00:0000│ rsp 0x7fff..e288 —▸ 0x401234 (main+48)  ← ret addr
# 01:0008│     0x7fff..e290 ◂— 0x0                 ← old rbp
# 02:0010│     0x7fff..e298 ◂— 'AAAAAAA'           ← 버퍼
# ...

플래그 레지스터 분석

# RFLAGS 전체 보기
pwndbg> p/t $eflags      # 2진수로 — 각 비트가 플래그
pwndbg> info registers eflags

# 플래그 비트 위치 (주요 플래그)
# CF  bit 0  — Carry Flag (올림, 빌림)
# PF  bit 2  — Parity Flag
# ZF  bit 6  — Zero Flag (비교 결과 0일 때)
# SF  bit 7  — Sign Flag (음수일 때)
# TF  bit 8  — Trap Flag (단계 실행)
# IF  bit 9  — Interrupt Enable
# OF  bit 11 — Overflow Flag

# 특정 플래그 확인
pwndbg> p ($eflags >> 6) & 1   # ZF 값 (0 또는 1)
pwndbg> p ($eflags >> 7) & 1   # SF 값

스택 프레임 완전 분석

# 현재 함수의 스택 프레임 구조 파악

; 표준 함수 프롤로그 이후 상태:
; [RSP]     = 리턴 주소 (함수 호출 직후엔 여기)
; [RSP]     = (PUSH RBP 후) 이전 RBP
; [RSP+8]   = 리턴 주소
; RBP       = 현재 스택 프레임 베이스
; [RBP-N]   = 로컬 변수들
; [RBP+8]   = 첫 번째 인자 (x86 cdecl)
; [RBP+10]  = 두 번째 인자

# 로컬 변수 위치 계산
pwndbg> p $rbp - 0x10         # 로컬 변수 4개 위 (4*4=16)
pwndbg> x/4wx $rbp - 0x10    # 해당 위치 값 확인

# 함수 인자 위치 (x86_64 System V ABI)
# 인자 1 = RDI
# 인자 2 = RSI
# 인자 3 = RDX
# 인자 4 = RCX
# 인자 5 = R8
# 인자 6 = R9
# 인자 7+ = 스택 (RBP+0x10, RBP+0x18, ...)

frame / backtrace — 콜 스택 탐색

# 현재 콜 스택
pwndbg> bt               # backtrace
pwndbg> bt 5             # 5 프레임만
pwndbg> bt full          # 로컬 변수 포함

# 특정 프레임으로 이동
pwndbg> frame 0          # 현재 함수
pwndbg> frame 2          # 호출자의 호출자
pwndbg> up               # 한 단계 위 (호출자로)
pwndbg> down             # 한 단계 아래

# 프레임 이동 후 로컬 변수 보기
pwndbg> frame 2
pwndbg> info locals      # 해당 프레임의 로컬 변수
pwndbg> info args        # 해당 프레임의 인자

리턴 주소 바로 찾기

telescope $rsp에서 첫 번째 CODE 색상(빨간색 계열) 값이 리턴 주소다. 버퍼 오버플로 분석에서 "리턴 주소가 어떻게 바뀌었나"를 확인할 때 telescope $rsp 20을 쓰면 한 번에 파악된다.
