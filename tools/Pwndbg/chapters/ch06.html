버퍼 오버플로의 핵심 — 리턴 주소까지의 거리를 정확히 계산한다

📌
이 챕터에서 배울 것

De Bruijn 패턴 원리, cyclic 생성·검색, 크래시 직후 오프셋 계산, 32/64비트 차이, 파일로 저장하기, 실전 BOF 분석 워크플로우.

왜 cyclic 패턴인가 — AAAA로는 안 되는 이유

버퍼 오버플로를 확인하려고 "A" * 200을 넣으면 크래시는 나지만, 리턴 주소가 0x41414141로 덮여서 "오버플로는 됐는데 몇 바이트 떨어져 있지?"를 알 수 없다. 200바이트 중 어디서부터 리턴 주소가 시작됐는지 특정이 안 된다.

De Bruijn 패턴(cyclic)은 어떤 연속된 4(또는 8)바이트를 보더라도 패턴 안에서 딱 한 군데만 나타나는 문자열이다. 크래시 직후 리턴 주소에 남은 값을 보면 "이 4바이트는 패턴의 N번째 위치에 있다"를 즉시 계산할 수 있다.

cyclic 명령어 사용법

# 패턴 생성
pwndbg> cyclic 100       # 100바이트 패턴 생성
# aaaabaaacaaadaaaeaaafaaagaaahaaaiaaajaaakaaalaaama...

pwndbg> cyclic 200       # 200바이트

# 패턴을 파일로 저장 (2024.02+ 기능)
pwndbg> cyclic 200 > /tmp/payload.txt
pwndbg> run < /tmp/payload.txt

# 오프셋 찾기 — 크래시 후 RIP/RSP 값으로
pwndbg> cyclic -l 0x6161616a        # 이 4바이트가 몇 번째인지
pwndbg> cyclic -l jaaa              # ASCII로도 가능
# 출력: 36  → 오프셋 = 36바이트

# 64비트 환경 — 8바이트씩 검색
pwndbg> cyclic -n 8 200             # 8바이트 단위 패턴 생성
pwndbg> cyclic -n 8 -l 0x6161616a6161616b  # 8바이트 오프셋 검색

32비트 vs 64비트 — 오프셋 계산 차이

# 32비트: RIP 대신 EIP, 4바이트 단위
pwndbg> cyclic 150
# 크래시 후: EIP = 0x6161616a

pwndbg> cyclic -l 0x6161616a     # -n 옵션 없으면 기본 4바이트
# 36

# 또는 EIP 직접 확인
pwndbg> p $eip
# $1 = (void (*)()) 0x6161616a
pwndbg> cyclic -l $eip
# 64비트: RIP은 직접 덮기 어려움 (canonical 주소 제한)
# 크래시 시 fault addr은 RSP의 값을 보는 게 더 정확

pwndbg> cyclic -n 8 200          # 8바이트 단위 패턴
# 크래시 후 RSP에 남은 값으로
pwndbg> x/gx $rsp                # RSP 역참조
# 0x7fff... 0x6161616a61616169

pwndbg> cyclic -n 8 -l 0x6161616a61616169
# 72 → 리턴 주소 오프셋

# 주의: 64비트 주소는 상위 2바이트가 0x0000이어야 함
# 0xdeadbeefcafebabe 같은 주소는 SIGSEGV 전에 이미 걸림

cyclic 응용 — 스택 카나리 위치 찾기

# 스택 카나리가 있을 때 (Stack: Canary found)
# 카나리는 로컬 변수 뒤, 리턴 주소 앞에 위치
# 카나리를 덮으면 __stack_chk_fail()이 호출되며 종료

# 카나리 값 확인 방법
pwndbg> p *(long*)($rbp - 8)    # 카나리는 보통 RBP-8
# $1 = 0x7d3a8e49c98f7e00    ← 하위 바이트가 항상 \x00

# 카나리 위치 매핑
# [버퍼] ... [카나리 8B] [old RBP 8B] [리턴주소 8B]
# cyclic로 카나리 앞까지 오프셋 확인 후
# 카나리는 유지, 리턴 주소만 덮기
⚠️
ASLR과 PIE에서 오프셋의 의미

pwndbg는 기본적으로 ASLR을 끈다(disable-randomization on). 실제 원격 서버에서는 ASLR이 켜져 있으므로 매번 주소가 달라진다. 로컬에서 찾은 오프셋(리턴 주소까지 거리)은 변하지 않지만, 덮어쓸 목표 주소는 libc 릭이나 PIE 릭 등으로 런타임에 계산해야 한다.
