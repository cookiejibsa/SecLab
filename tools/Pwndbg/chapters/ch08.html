malloc 청크 구조 — 먼저 이해해야 명령어가 보인다

glibc의 malloc은 청크(chunk) 단위로 메모리를 관리한다. 청크는 헤더 + 사용자 데이터로 구성된다. 

; malloc 청크 메모리 레이아웃 (64비트)
; 주소       내용
; chunk →  [prev_size  8B]  ← 이전 청크 크기 (free 시 사용)
;          [size       8B]  ← 현재 청크 크기 + 플래그 3비트
; mem →    [fd         8B]  ← (free 시) 다음 청크 포인터
;          [bk         8B]  ← (free 시) 이전 청크 포인터
;          [user data ...] ← malloc()이 반환하는 포인터는 여기!

; size 필드 하위 3비트:
;   bit 0 (P) = prev_in_use: 이전 청크가 사용 중이면 1
;   bit 1 (M) = mmap'd: mmap으로 할당됐으면 1
;   bit 2 (A) = non-main-arena: 메인 아레나가 아니면 1

; 예: size = 0x31 이면 실제 크기 = 0x30, P=1(이전 청크 사용 중)

vis_heap_chunks — 힙 시각화

pwndbg 최고 기능 중 하나다. 힙을 청크 단위로 색상 구분해서 보여준다. 어떤 청크가 할당 중이고 어떤 게 free인지, 오버플로가 어디를 침범했는지 한눈에 보인다. 

# 기본 사용
pwndbg> vis_heap_chunks

# 출력 예시 (색상은 터미널에서 확인)
# 0x555555559000  0x0000000000000000  0x0000000000000291  ................ ← tcache struct
# 0x555555559290  0x0000000000000000  0x0000000000000031  ........1.......  
# 0x5555555592a0  0x4141414141414141  0x4141414141414141  AAAAAAAAAAAAAAAA ← 사용 중 청크 (A로 가득)
# 0x5555555592b0  0x4141414141414141  0x0000000000000000  AAAAAAAA........
# 0x5555555592c0  0x0000000000000000  0x0000000000000031  ........1....... ← free 청크
# 0x5555555592d0  0x0000000000000000  0x0000555555559010  .........@UUU... ← fd 포인터

# 옵션
pwndbg> vis_heap_chunks 0x555555559290    # 특정 주소부터
pwndbg> vis_heap_chunks --no-color       # 색상 없이

tcache 구조 이해 — 현대 힙 공격의 핵심

glibc 2.26(2017)부터 도입된 스레드별 캐시다. 0x410 바이트 이하 청크를 free하면 tcache에 먼저 들어간다. 각 크기별로 최대 7개를 LIFO로 보관한다. 락이 없어서 빠르지만, 검증도 적어서 공격하기 쉽다. 

# tcache 내부 구조 확인
pwndbg> tcache_perthread_struct
# tcache_perthread_struct (0x555555559010) {
#   counts = {3, 0, 2, ...}     ← 각 크기별 개수
#   entries = {0x5555..., ...}  ← 각 크기별 첫 번째 청크
# }

# mp_ 구조체 (malloc parameters)
pwndbg> mp
# { tcache_bins = 64, tcache_max_bytes = 1032, tcache_count = 7, ... }

# tcache 크기 범위: 0x20 ~ 0x410 (64비트), 0x08 단위
# 크기 계산: malloc(0x28) → 청크 크기 0x30 (= 0x28 + 8헤더, 16정렬)

double free 탐지

# 같은 청크를 두 번 free하면...
# glibc 2.26 초기: 검사 없음 → 쉬운 double free
# glibc 2.29+: tcache에 key 필드 추가, 재진입 탐지
# glibc 2.32+: safe-linking으로 fd 포인터 암호화

# pwndbg로 double free 확인
# vis_heap_chunks에서 같은 청크가 빈에 두 번 나오면 double free
pwndbg> tcachebins
# 0x20 [2]: 0x555555559290 —▸ 0x555555559290  ← 같은 주소가 두 번!

# try_free — free() 시 어떤 일이 일어날지 미리 확인
pwndbg> try_free 0x555555559290
# Doing free with 0x555555559290...
# Would place into tcachebins[0x20][0/7]

실전 힙 분석 시나리오 — UAF(Use After Free)

# UAF 시나리오: free 후에도 포인터를 통해 접근

# 1. malloc & free 상황 재현
pwndbg> break *main+100    # free() 직후에 BP
pwndbg> run

# 2. free 직후 상태 확인
pwndbg> vis_heap_chunks
# 0x555555559290  ← 이 청크가 tcache에 들어감

pwndbg> tcachebins
# 0x30 [1]: 0x555555559290 ◂— 0x0

# 3. fd 포인터 확인 (tcache에서 다음 청크 포인터)
pwndbg> x/2gx 0x555555559290
# 0x555555559290:  0x0000000000000000  ← fd (null = 리스트 끝)
# 0x555555559298:  0x0000555555559010  ← key (double free 방지)

# 4. UAF 후 같은 주소로 다시 접근하면 fd 포인터 조작 가능
# → 다음 malloc은 fd가 가리키는 주소를 반환
# → 임의 주소에 malloc! (tcache poisoning)
⚠️
safe-linking (glibc 2.32+)

glibc 2.32부터 tcache/fastbin의 fd 포인터가 XOR 암호화된다 (fd ^ (chunk_addr >> 12)). pwndbg는 이를 자동으로 디코딩해서 보여주지만, 익스플로잇 코드에서 직접 fd를 조작하려면 암호화를 거쳐야 한다. Ubuntu 22.04(glibc 2.35), 24.04(glibc 2.39) 대상에서는 반드시 고려해야 한다.
