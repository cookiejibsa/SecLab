Chapter 01

Metasploit이란 무엇인가?

왜 보안 전문가들은 20년이 넘도록 이 도구를 놓지 않는가 — 역사, 구조, 그리고 침투 테스트 생태계에서의 위치

🤔 왜 이런 도구가 필요했을까?

2003년 이전, 보안 연구자들이 시스템 취약점을 테스트하는 과정을 상상해보세요. 새로운 취약점이 발견되면, 그 취약점을 공격하는 코드(익스플로잇)를 연구자가 직접 C나 Python으로 처음부터 작성해야 했습니다. 운영체제가 다르면? 처음부터 다시. 대상 서비스 버전이 다르면? 또 수정. 공격 성공 후 원하는 작업(파일 다운로드, 명령 실행 등)을 하려면? 그것도 별도로 개발.

이 과정은 엄청나게 비효율적이었습니다. 취약점 하나를 테스트하는 데 며칠이 걸렸고, 같은 작업을 수십 명의 연구자가 제각각 반복하고 있었습니다. 마치 건물을 지을 때 망치를 쓰고 나면 버리고, 다음 못을 박을 때 새 망치를 만드는 것과 같았습니다.

💡
Metasploit의 핵심 아이디어

"익스플로잇 코드와 그 이후 할 작업(페이로드)을 분리하자. 그리고 둘을 마음대로 조합할 수 있게 만들자." — 이 단순한 아이디어가 보안 업계를 바꿔놓았습니다.

HD Moore는 이 문제를 해결하기 위해 2003년 Perl로 Metasploit의 첫 버전을 작성했습니다. "재사용 가능한 익스플로잇 라이브러리"라는 개념을 도입해, 한 번 작성한 공격 코드를 표준화된 방식으로 관리하고 조합할 수 있게 한 것입니다. 2007년 Ruby로 전면 재작성되면서 현재 우리가 알고 있는 형태로 발전했고, 2009년 Rapid7이 인수하면서 상업적 지원도 받게 되었습니다.

🏗️ Metasploit의 전체 구조 — 프레임워크를 해부하다

Metasploit을 "해킹 도구"라고 단순하게 부르는 사람들은 그 실제 규모를 과소평가하는 것입니다. Metasploit Framework는 수천 개의 모듈로 이루어진 하나의 플랫폼입니다. 그 구조를 레이어 별로 살펴보겠습니다.

🗡️ Exploits

취약점을 실제로 공격하는 코드. CVE 번호에 대응하는 수천 개의 모듈이 있습니다. 버퍼 오버플로우부터 웹 애플리케이션 취약점까지 포함.

📦 Payloads

익스플로잇 성공 후 대상 시스템에서 실행될 코드. 리버스 셸, Meterpreter, 단순 명령 실행 등 다양한 형태.

🔍 Auxiliaries

직접적인 공격 외의 작업을 수행하는 모듈. 포트 스캐너, 버전 감지기, 무차별 대입 도구, 스니퍼 등.

⚙️ Post Modules

시스템 침투 후 사용하는 모듈. 권한 상승, 자격증명 수집, 피벗 설정, 지속성 확보 등.

🎭 Encoders

페이로드를 인코딩하여 패턴 기반 탐지를 우회합니다. Shikata Ga Nai가 가장 유명한 XOR 폴리모픽 인코더.

🚫 NOPs

No Operation 슬라이드. 버퍼 오버플로우 익스플로잇에서 주소 정렬 패딩으로 사용되는 특수 코드.

아키텍처 계층

이 모듈들은 단순히 나열된 게 아닙니다. Rex(Ruby Extension Library) 라이브러리 위에 MSF Core가 올라가고, 그 위에 각 모듈들이 구동됩니다. 사용자가 보는 인터페이스(msfconsole, msfweb, armitage)는 이 Core와 통신하는 최상위 레이어입니다.

📐 Metasploit 아키텍처 계층도 
┌─────────────────────────────────────────────────────────┐
│                    User Interfaces                      │
│         msfconsole  │  msfweb  │  Armitage  │  API      │
├─────────────────────────────────────────────────────────┤
│                       MSF Core                          │
│   세션 관리   │   모듈 로딩   │  이벤트 디스패치  │     DB     │
├─────────────────────────────────────────────────────────┤
│                       MSF Base                          │
│             공통 유틸리티, 플러그인 시스템, 헬퍼               │
├─────────────────────────────────────────────────────────┤
│                         Rex                             │
│        소켓  │  프로토콜  │  인코딩  │  암호화  │   로깅       │
├─────────────────────────────────────────────────────────┤
│                      Ruby + OS                          │
└─────────────────────────────────────────────────────────┘

각 모듈 위치:
modules/
├── exploits/        ← 취약점 공격 코드
├── payloads/        ← 침투 후 실행 코드
│   ├── singles/     ← 자체완결형 페이로드
│   ├── stagers/     ← 2단계 연결 수립 코드
│   └── stages/      ← 2단계 실제 기능 코드
├── auxiliary/       ← 스캔, 열거, 퍼징
├── post/            ← 침투 후 작업
├── encoders/        ← 페이로드 인코더
└── nops/            ← NOP 생성기

숫자로 보면 Metasploit의 위상이 더 명확히 드러납니다.

구분 수량 설명

💡
MSF Community vs Pro

무료 오픈소스 버전인 Metasploit Framework로도 이 가이드의 모든 내용을 실습할 수 있습니다. Metasploit Pro는 Rapid7이 판매하는 상업 버전으로 GUI, 자동화, 보고서 기능이 추가됩니다.

🔄 침투 테스트 방법론에서의 위치

Metasploit을 도구 하나로 보면 그 힘을 반밖에 못 씁니다. 침투 테스트는 체계적인 프로세스이고, Metasploit은 그 각 단계에서 서로 다른 역할을 합니다.

  1. 1
    정찰 (Reconnaissance)

    대상 시스템에 대한 정보 수집. Metasploit의 Auxiliary 스캐너 모듈, Nmap 통합을 통해 열린 포트, 실행 중인 서비스, 운영체제 버전 등을 파악합니다.

  2. 2
    스캔 & 열거 (Scanning & Enumeration)

    발견한 서비스의 세부 정보를 더 깊이 파악. SMB 공유, SSH 버전, HTTP 헤더, 데이터베이스 정보 등. 이 단계에서 exploit 가능한 취약점을 식별합니다.

  3. 3
    취약점 악용 (Exploitation)

    식별된 취약점에 적합한 Exploit 모듈을 선택하고 적절한 Payload와 조합해 대상 시스템에 실제 침투를 시도합니다.

  4. 4
    침투 후 작업 (Post-Exploitation)

    시스템 접근 권한을 얻은 후 목표 달성. 데이터 수집, 권한 상승, 내부 네트워크 이동, 지속성 확보. Meterpreter와 Post 모듈이 핵심입니다.

  5. 5
    보고 (Reporting)

    발견한 취약점과 실증된 위험성을 문서화. 어떤 경로로 침투했는지, 어떤 데이터에 접근 가능했는지, 보완 방법은 무엇인지를 명확히 기록합니다.

⚖️ Metasploit을 배운다는 것의 의미

많은 분들이 이런 질문을 가지고 있습니다. "이걸 배우면 범죄자가 되는 건 아닌가요?" 오히려 반대입니다. 공격 기술을 이해하지 못한 채로 방어만 공부하는 것은, 바이러스를 본 적 없는 의사가 면역학을 공부하는 것과 같습니다.

✅ Metasploit의 합법적 사용

  • 자신이 소유한 시스템 테스트
  • 계약에 의한 침투 테스트(펜테스트)
  • 보안 연구 및 교육 환경에서 실습
  • CTF(Capture the Flag) 해킹 대회 참가
  • 버그 바운티 프로그램 참여
  • 레드팀/블루팀 훈련

❌ 불법적 사용 (절대 하지 말 것)

  • 허가 없는 타인의 시스템 스캔
  • 동의 없는 취약점 익스플로잇 시도
  • 데이터 무단 접근 및 탈취
  • 서비스 방해(DoS) 공격
  • 악성코드 배포 목적 페이로드 생성
⛔
대한민국 법적 처벌 기준

허가 없이 타인의 시스템에 접근하는 행위는 정보통신망 이용촉진 및 정보보호 등에 관한 법률(정보통신망법) 제48조 위반으로 5년 이하 징역 또는 5천만 원 이하 벌금에 처해질 수 있습니다. 또한 형법 제347조의2(컴퓨터등 사용사기) 등도 적용될 수 있습니다.

🆚 다른 도구들과의 비교

Metasploit이 "보안의 전부"는 아닙니다. 실제 침투 테스트 현장에서는 다양한 도구들이 각자의 역할을 맡습니다.

Metasploit vs Nmap

Nmap은 포트 스캔과 서비스 감지에 특화된 도구입니다. Metasploit은 Nmap을 내장하고 있습니다 — db_nmap 명령어로 Nmap 스캔 결과가 자동으로 Metasploit 데이터베이스에 저장되어 이후 공격에 바로 활용됩니다. 즉, 둘은 경쟁 관계가 아니라 함께 씁니다.

Metasploit vs Burp Suite

Burp Suite는 웹 애플리케이션 보안 테스트에 특화되어 있습니다. HTTP 프록시, 인터셉터, 스캐너를 통해 SQL 인젝션, XSS 같은 웹 취약점을 찾는 데 강합니다. Metasploit은 발견된 웹 취약점을 실제로 익스플로잇하는 단계에서 활용됩니다. 실무에서는 Burp로 취약점 찾고, MSF로 익스플로잇하는 흐름이 일반적입니다.

Metasploit vs Cobalt Strike

Cobalt Strike는 고급 레드팀 작전을 위한 상업 도구(약 $5,900/년)입니다. Beacon이라는 C2(Command & Control) 에이전트가 강력하며, 탐지 우회와 팀 협업 기능에서 MSF보다 앞섭니다. 반면 Metasploit은 무료이고 익스플로잇 모듈 수가 훨씬 많습니다. 대규모 기업 레드팀은 둘을 함께 씁니다.

Metasploit vs Nikto

Nikto는 웹 서버 취약점 스캐너입니다. 알려진 취약한 파일, 잘못된 설정, 오래된 소프트웨어 버전을 빠르게 감지하는 데 특화되어 있습니다. 탐지 중심의 Nikto와 달리, Metasploit의 HTTP 관련 모듈들은 실제 공격 가능성 검증에 초점을 맞춥니다.

🎓 자격증과 커리어 로드맵

Metasploit을 마스터하면 열리는 커리어 경로들입니다.

🏆 OSCP (Offensive Security Certified Professional) ▼

침투 테스터가 가장 인정받는 자격증입니다. 24시간 실기 시험에서 여러 취약한 머신을 실제로 침투해야 합니다. Metasploit 사용이 제한적으로만 허용되는 것으로 유명한데, 이는 도구에 의존하지 않고 원리를 이해하도록 설계되었기 때문입니다. 역설적으로 Metasploit의 동작 원리를 깊이 이해해야 OSCP를 통과할 수 있습니다.

🎯 CEH (Certified Ethical Hacker) ▼

EC-Council의 자격증으로, 이론 중심의 시험입니다. Metasploit 관련 문제가 다수 출제됩니다. OSCP보다 취득이 쉽고 아시아 권역에서 인정도가 높아, 국내 기업 채용에서 자주 언급됩니다.

🔴 eJPT / eCPPT (eLearnSecurity) ▼

입문자에게 추천하는 실기 위주 자격증입니다. eJPT는 Metasploit을 적극적으로 활용하는 시험이라 이 가이드북을 끝내고 도전하기 좋습니다. eCPPT는 중급 수준으로 피벗, 버퍼 오버플로우 등을 다룹니다.

🏢 국내 자격증 — CPPG, 정보보안기사 ▼

정보보안기사는 국가공인 자격증으로 실무형보다 법령·정책 비중이 높습니다. 직무 상 보안 관련 일을 하시는 분들에게 기본 자격으로 요구되는 경우가 많습니다. 단독으로 취득하기보다는 OSCP, CEH와 함께 취득하는 경우가 많습니다.
