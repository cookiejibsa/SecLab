함수 인식 & 호출 규약

디컴파일된 코드에서 함수 경계를 찾고, 호출 규약을 구분한다

함수 인식의 기준

스트립된(stripped) 바이너리에는 함수 이름이 없다. 디스어셈블러는 패턴으로 함수 경계를 추측한다. Ghidra의 Auto Analysis가 자동으로 해주지만, 놓치거나 잘못 분류한 함수들이 있다. 수동으로 찾는 기준을 알아야 그 경우를 처리할 수 있다.

함수 시작 신호: push rbp로 시작하는 프롤로그, CALL 명령의 타겟 주소, 다른 함수의 XRef 타겟.

함수 끝 신호: ret/retn 명령어, 또는 jmp로 다른 함수 시작으로 점프 (tail call optimization).

호출 규약 (Calling Convention)

규약인자 전달스택 정리주로 쓰이는 곳
cdecl오른쪽→왼쪽, 스택호출자(caller)C 함수 (x86)
stdcall오른쪽→왼쪽, 스택피호출자(callee)Win32 API (x86)
fastcallECX, EDX → 스택피호출자MSVC 최적화 (x86)
x64 WindowsRCX, RDX, R8, R9 → 스택호출자Windows 64비트 모두
System V AMD64RDI, RSI, RDX, RCX, R8, R9 → 스택호출자Linux/macOS 64비트
thiscallECX = this 포인터피호출자C++ 멤버 함수 (MSVC)

Shadow Space (Windows x64 전용)

Windows x64 ABI에서는 레지스터로 인자를 전달하더라도, 호출자가 스택에 32바이트(4 * 8 = 32)의 "Shadow Space"를 예약해야 한다. 이 공간은 callee가 RCX/RDX/R8/R9를 저장하는 데 쓸 수 있는 예약 공간이다. Linux x64에는 없는 개념이라 헷갈리기 쉽다. 

; Windows x64 함수 호출 패턴
sub  rsp, 0x28      ; 0x20 (shadow) + 0x8 (정렬)
mov  rcx, param1   ; 1번째 인자
mov  rdx, param2   ; 2번째 인자
call target_func
add  rsp, 0x28      ; 스택 복원

가상 함수 테이블 (vtable) 인식

C++ 바이너리에서 polymorphism은 vtable로 구현된다. 객체 포인터의 첫 8바이트가 vtable 포인터다.

; vtable을 통한 가상 함수 호출
mov  rax, [rcx]          ; rcx = 객체 포인터, rax = vtable 주소
call [rax + 0x18]       ; vtable[3] 호출 (0x18 / 8 = 3번째 가상 함수)

Ghidra에서 .rdata 섹션의 포인터 배열을 보면 vtable을 찾을 수 있다. 각 항목이 .text 내 함수를 가리킨다.
