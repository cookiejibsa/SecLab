Chapter 12 · Part 4 — 난독화 해제

패킹 & 언패킹

원본 코드를 꺼내기 전까지는 진짜 분석이 시작되지 않는다

패킹이란

패커(Packer)는 실행 파일을 압축하거나 암호화해서, 원본 코드를 숨기는 도구다. 실행 시 패커 스텁(stub)이 먼저 실행되어 원본 코드를 메모리에 복원하고, 진입점(OEP)으로 점프한다. 정적 분석으로는 스텁만 보이고 원본 코드는 보이지 않는다.

패킹 탐지

# DIE (Detect It Easy)로 패커 확인
die.exe target.exe

# UPX 탐지 예시 출력
PE64
    Packer: UPX(3.96)[NRV,brute]

# pestudio에서 확인
# 섹션 이름이 UPX0, UPX1이면 UPX
# 엔트로피 > 7.5면 패킹/암호화 의심
# 섹션이 1~2개뿐이면 패킹 가능성 높음

UPX 언패킹

UPX는 가장 흔한 오픈소스 패커다. 공식 언패킹 옵션이 있다.

# UPX 자동 언패킹
upx -d target.exe -o unpacked.exe

# 언패킹 후 확인
die.exe unpacked.exe
# → Compiler: Microsoft Visual C/C++ (패커 없음)
⚠️
수정된 UPX

악성코드는 UPX 시그니처를 변조해서 자동 언패킹을 막는다. 섹션 이름을 바꾸거나 매직 바이트를 수정한다. 이 경우 수동 언패킹이 필요하다.

수동 언패킹 — OEP(Original Entry Point) 찾기

패킹된 바이너리는 패커 스텁이 먼저 실행되고, 원본 코드의 진입점(OEP)으로 점프한다. 그 점프 직전에 멈추면 원본 코드가 메모리에 완전히 복원된 상태다.

  • 1
    ESP 기법 — 가장 일반적인 방법
    패커 스텁 시작 시 레지스터를 스택에 push한다. 이 스택 위치에 하드웨어 BP(쓰기 접근)를 걸면 pop 후 OEP 직전에 멈춘다.
  • 2
    원본 섹션에 메모리 BP — 원본 코드가 복원될 영역에 실행 BP
    패킹된 바이너리의 원본 코드 섹션(보통 VA 0x401000 부근)에 메모리 실행 BP를 설정한다.
  • 3
    OEP에서 덤프 — OllyDumpEx로 메모리 덤프
    OEP에서 멈춘 상태에서 전체 프로세스 메모리를 덤프한다.
  • 4
    IAT 복구 — Scylla로 임포트 테이블 재구성
    덤프 파일의 IAT는 런타임 주소로 채워져 있어서 정적 분석 시 작동하지 않는다. Scylla로 복구한다.
; ESP 기법 상세
; 1. x64dbg에서 패킹된 바이너리 로드
; 2. 첫 번째 명령어에서 멈춘 상태 확인 (pushad 또는 push rbp 등)
; 3. F8로 한 스텝 → RSP 값 확인
; 4. 덤프 창에서 RSP 주소로 이동
; 5. 해당 주소에서 우클릭 → Breakpoint → Hardware, on Access
; 6. F9로 실행 → OEP 직전에서 멈춤
; 7. Plugins → OllyDumpEx → Dump
; 8. Plugins → Scylla → IAT Autosearch → Get Imports → Fix Dump

커스텀 패커 분석

UPX 이외의 커스텀 패커는 스텁 로직을 직접 분석해야 한다. 복호화 루프를 찾는 것이 핵심이다.

; 전형적인 커스텀 패커 스텁 패턴
mov  esi, packed_data   ; 암호화된 데이터 시작
mov  edi, target_addr   ; 복원될 주소
mov  ecx, size          ; 크기
decrypt_loop:
mov  al, [esi]
xor  al, 0x42           ; XOR 복호화
mov  [edi], al
inc  esi
inc  edi
loop decrypt_loop
jmp  target_addr         ; OEP로 점프

; 이 경우: loop 직후 (jmp target_addr)에 BP → OEP에서 덤프
💡
언패킹 성공 확인

덤프 후 DIE로 다시 확인했을 때 패커 시그니처가 없고 컴파일러 정보가 보이면 성공이다. Ghidra에 다시 던져서 IAT가 정상적으로 채워졌는지 확인한다.
