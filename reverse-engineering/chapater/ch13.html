암호화 루틴 식별 & 키 추출

바이너리에서 암호화를 찾고, 런타임 키를 꺼낸다

암호화 루틴을 찾는 방법

악성코드는 C2 통신 암호화, 페이로드 보호, 설정 데이터 숨김 등에 암호화를 쓴다. 소스코드 없이 어떤 알고리즘인지, 키가 뭔지를 알아내야 한다. 세 가지 단서로 접근한다: 상수값, API 임포트, 코드 패턴.

알고리즘별 식별 방법

XOR 암호화

가장 단순하고 흔하다. 같은 키로 암호화/복호화가 같은 연산이라 구현이 쉽다.

; XOR 복호화 루프 패턴
mov  ecx, length
xor_loop:
xor  byte [rdi], 0x5A   ; 고정 키 XOR
inc  rdi
loop xor_loop

; 다중 바이트 키 XOR
mov  al, [rdi]
xor  al, [rsi + rcx % key_len]  ; 키 순환

키 추출: XOR은 plaintext ^ ciphertext = key. 알려진 평문(예: "MZ" 헤더)이 있으면 키를 역산할 수 있다.

RC4

스트림 암호. KSA(Key Scheduling Algorithm)와 PRGA(Pseudo-Random Generation Algorithm) 두 단계로 구성된다.

식별 패턴: 256바이트 S-box 초기화 루프 (for i=0; i<256; i++ s[i]=i), 이후 키로 교환하는 이중 루프.

; KSA 단계 패턴 (Ghidra 디컴파일)
for (i=0; i<256; i++) s[i] = i;           // S-box 초기화
for (i=0, j=0; i<256; i++) {
    j = (j + s[i] + key[i % keylen]) % 256;
    swap(s[i], s[j]);                        // KSA
}

키 추출: KSA 진입 직전에 BP → key 포인터의 메모리 덤프.

AES

블록 암호. S-box 상수값이 특징적이라 자동 도구로 식별 가능하다.

식별: 바이너리 내 AES S-box (0x63, 0x7c, 0x77, 0x7b, 0xf2...) 또는 CryptAcquireContext + PROV_RSA_AES API 임포트.

# findcrypt-ghidra 플러그인: Ghidra에서 암호화 상수 자동 탐지
# Script Manager → FindCrypt.py 실행
# 결과: AES_SBOX found at 0x40A000

키 추출: AES는 키 스케줄링(KeyExpansion) 시작 전에 BP. RCX/RDI(키 포인터) 메모리 16/24/32바이트 덤프.

Frida로 런타임 키 추출

// CryptEncrypt 전 키 덤프 스크립트
Interceptor.attach(Module.findExportByName('advapi32.dll', 'CryptEncrypt'), {
    onEnter: function(args) {
        var hKey = args[0];
        // hKey에서 키 길이 추출 (구조체 오프셋은 Windows 버전마다 다름)
        console.log('CryptEncrypt called, hKey: ' + hKey);
    }
});

// 더 직접적: 복호화 함수 직접 후킹
var decrypt = new NativeFunction(
    Module.findExportByName(null, 'decrypt_data'), 'void', ['pointer', 'int']
);
Interceptor.attach(decrypt, {
    onEnter: function(args) {
        console.log('decrypt key buf: ' + hexdump(args[0], {length: 32}));
    }
});
