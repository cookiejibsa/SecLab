Ghidra 설치, UI 구성, 기본 분석 흐름을 다룬다. CodeBrowser 고급 기능, 스크립팅(Jython/Java API), 플러그인 개발은 별도 Ghidra 심화 가이드에서 상세히 다룬다.

Ghidra가 하는 일

Ghidra는 바이너리를 두 단계로 읽는다. 먼저 디스어셈블해서 기계어를 어셈블리로 바꾸고, 그 다음 디컴파일해서 어셈블리를 C와 비슷한 의사코드(pseudo-code)로 올린다. 이 두 결과를 나란히 보면서 분석한다.

기본 워크플로우

  • 1
    프로젝트 생성
    File → New Project → Non-Shared Project. 프로젝트는 분석 결과(주석, 이름 변경 등)를 저장하는 컨테이너다.
  • 2
    바이너리 임포트
    바이너리를 드래그하거나 File → Import File. Ghidra가 포맷을 자동 감지한다.
  • 3
    Auto Analysis 실행
    더블클릭으로 CodeBrowser 열기 → "Analyze" 버튼 클릭. 기본 분석기를 모두 실행한다. 바이너리 크기에 따라 수초~수분 소요.
  • 4
    분석 시작
    Symbol Tree에서 Functions 펼치기 → entry 또는 main에서 시작.

기본 분석 시나리오: 함수 이름 복원

Ghidra가 분석한 직후에는 대부분의 함수가 FUN_00401000 같은 자동 생성 이름을 가진다. 분석 과정은 이 이름들을 의미 있는 이름으로 바꾸는 과정이다. 

/* Ghidra 디컴파일 초기 상태 */
void FUN_00401234(char *param_1, int param_2)
{
    int iVar1;
    char *pcVar2;

    iVar1 = FUN_00401100(param_1);
    if (iVar1 == param_2) {
        FUN_00401300("success");
    }
    return;
}

/* 분석 후 이름 변경 */
void check_password(char *input, int expected_hash)
{
    int actual_hash;
    
    actual_hash = compute_hash(input);
    if (actual_hash == expected_hash) {
        print_message("success");
    }
    return;
}

이름 변경은 N 키 하나로 한다. 함수 이름, 파라미터 이름, 지역변수 이름 모두 바꿀 수 있다.

문자열로 진입점 찾기

함수 이름이 없는 스트립된 바이너리에서 분석 시작점을 찾는 가장 빠른 방법은 문자열이다. 

; Window → Defined Strings 로 문자열 창 열기
; "password", "error", "success", "key", "flag" 등 의미있는 문자열 검색
; 해당 문자열을 더블클릭 → 참조 위치(XRef) 확인 → 해당 함수 분석
