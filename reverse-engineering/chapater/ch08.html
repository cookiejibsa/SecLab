Chapter 08 · Part 3 — 동적 분석

x64dbg 실습

Windows 환경 동적 분석의 핵심 툴 — 브레이크포인트부터 메모리 덤프까지

x64dbg 기본 레이아웃

x64dbg는 네 개의 주요 패널로 구성된다. 각 패널의 역할을 먼저 이해해야 효율적으로 쓸 수 있다.

패널위치역할
디스어셈블리 뷰좌상단현재 실행 위치의 코드. 노란 화살표가 EIP/RIP.
레지스터 뷰우상단모든 레지스터 현재값. 변경된 레지스터 빨간색 강조.
스택 뷰우하단현재 스택 상태. RSP가 가리키는 위치.
덤프 뷰좌하단임의 메모리 주소의 헥스 뷰.

필수 단축키

키동작설명
F9Run다음 브레이크포인트까지 실행
F8Step OverCALL을 함수 단위로 건너뜀
F7Step IntoCALL 안으로 들어감
F4Run to Cursor커서 위치까지 실행
F2브레이크포인트 토글현재 줄에 BP 설정/해제
Ctrl+G주소로 이동모듈+오프셋 형식 지원
Ctrl+B바이트 패턴 검색메모리 전체 검색
Alt+M메모리 맵로드된 모듈 전체 목록

브레이크포인트 전략

소프트웨어 브레이크포인트 (INT3)

가장 기본적인 방식. 해당 주소의 첫 바이트를 0xCC(INT3)로 교체한다. 실행 시 SIGTRAP 발생 → 디버거가 잡음.

장점: 무한정 설정 가능, 속도 빠름.

단점: IsDebuggerPresent나 코드 체크섬 검사에 걸릴 수 있음. 실행 코드에만 설정 가능.

; BP 설정 후 메모리 상태
; 원본: 48 89 4C 24 08 (mov [rsp+8], rcx)
; 변경: CC 89 4C 24 08 (int3 + 나머지)

하드웨어 브레이크포인트 (DR0~DR3)

CPU의 디버그 레지스터를 사용. 코드를 수정하지 않는다.

장점: 코드 수정 없음 → 체크섬 우회 가능. 실행/읽기/쓰기 트리거 모두 지원.

단점: 동시에 4개까지만 설정 가능.

설정 방법: 주소에서 우클릭 → Breakpoint → Hardware, on Execution

메모리 브레이크포인트

특정 메모리 영역에 대한 접근(읽기/쓰기/실행)이 발생하면 멈춘다.

용도: "이 버퍼에 언제 쓰는가?", "이 값이 언제 읽히는가?" 추적.

덤프 뷰에서 범위 선택 → 우클릭 → Breakpoint → Memory, on Access

조건부 브레이크포인트

특정 조건이 만족될 때만 멈춘다. 반복 호출되는 함수에서 특정 케이스만 잡을 때 유용하다.

; 예: CreateFileA가 "config.ini"를 열 때만 멈추기
; BP 설정 후 우클릭 → Edit Breakpoint → Condition 입력

; x64dbg 조건식 (rcx = 첫 번째 인자 = 파일 경로)
streq(rcx, "config.ini")

API 브레이크포인트 설정

; 심볼 이름으로 BP 설정 (Ctrl+G 또는 커맨드창)
bp CreateFileA
bp VirtualAlloc
bp MessageBoxA

; 특정 DLL 내 함수
bp kernel32.CreateFileA

; 로그만 남기고 멈추지 않기
bph CreateFileA log "CreateFile called: {rcx}"
💡
인자 확인 패턴

Windows API에 BP를 걸면 멈추는 순간 RCX/RDX/R8/R9가 인자다. RCX가 문자열 포인터면 덤프 창에서 Ctrl+G로 RCX 값으로 이동해서 확인한다.

메모리 덤프

언패킹 후 또는 런타임에 복호화된 코드를 파일로 저장해야 할 때 사용한다.

; 플러그인: OllyDumpEx 사용
; Plugins → OllyDumpEx → Dump Process

; 또는 메모리 맵에서 특정 영역 우클릭 → Dump Memory to File

; 커맨드창으로 특정 범위 덤프
savedata "C:\dump.bin", 0x401000, 0x1000
