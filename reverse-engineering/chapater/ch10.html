API 모니터링

실행을 보지 않고 행위를 본다 — 블랙박스 분석 접근법

블랙박스 분석의 개념

디버거 없이 프로그램이 무엇을 하는지 관찰하는 방법이 있다. OS와의 인터페이스 — 파일 접근, 레지스트리, 네트워크, 프로세스 생성 — 를 모니터링하면 내부 구현을 몰라도 행위를 파악할 수 있다. 악성코드 초기 분석에 특히 효과적이다.

Process Monitor (Procmon)

SysInternals의 Procmon은 Windows에서 파일/레지스트리/네트워크/프로세스 이벤트를 실시간으로 로깅한다.

효과적인 필터 설정

; 분석 대상만 보기
Process Name is malware.exe → Include

; 노이즈 제거
Result is SUCCESS → 일단 Include (실패 이벤트 제외)
Path contains \Windows\System32 → Exclude (시스템 접근 제거)

; 관심 이벤트만
Operation is WriteFile → Include
Operation is RegSetValue → Include
Operation is Process Create → Include

주목할 이벤트 패턴

이벤트의미
%APPDATA%\*.exe 쓰기자기 복제 / 드롭퍼
HKCU\Run 레지스트리 쓰기시작 프로그램 등록 (지속성)
CreateProcess → cmd.exe쉘 명령 실행
%TEMP%\*.dll 쓰기 후 LoadLibraryDLL 드롭 & 로드
수십~수백 개의 파일 쓰기 + .enc 확장자랜섬웨어 암호화

API Monitor

Win32 API 호출을 함수 단위로 캡처한다. 인자값과 반환값까지 볼 수 있어서 Procmon보다 세밀한 분석이 가능하다.

; API Monitor 설정
; 1. 모니터링할 API 그룹 선택 (Crypto, Networking, Process 등)
; 2. File → Monitor New Process → 대상 바이너리 선택
; 3. API 호출 목록에서 함수명/인자/반환값 확인

; 출력 예시
CryptAcquireContextA(NULL, NULL, NULL, PROV_RSA_AES, CRYPT_VERIFYCONTEXT) → TRUE
CryptGenKey(hProv, CALG_AES_256, CRYPT_EXPORTABLE, &hKey) → TRUE
CryptEncrypt(hKey, 0, TRUE, 0, pbData, &dwDataLen, dwBufLen) → TRUE

strace / ltrace (Linux)

# 시스템 콜 추적
strace ./target

# 특정 시스템 콜만
strace -e trace=open,read,write,execve ./target

# 라이브러리 함수 추적
ltrace ./target

# 실행 중인 프로세스에 attach
strace -p 1234

# 출력 저장
strace -o strace.log ./target
💡
조합 분석 워크플로우

Procmon으로 큰 그림의 행위를 파악 → 의심스러운 API를 API Monitor로 세부 확인 → 특정 함수에 x64dbg BP를 걸어 내부 분석. 이 세 단계가 악성코드 분석의 표준 접근법이다.
