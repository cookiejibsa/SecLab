Chapter 02 · Part 1 — 기초

환경 세팅

분석 환경을 구성한다 — 호스트를 오염시키지 않는 것이 핵심이다

왜 VM이 필수인가

악성코드나 크랙미를 분석할 때 대상 바이너리를 실행해야 하는 순간이 온다. 호스트 머신에서 직접 실행하면 파일 시스템 변조, 레지스트리 오염, 네트워크 C2 통신이 그대로 호스트에 영향을 준다. 가상 머신(VM)은 이 위험을 격리하는 샌드박스다. 분석 전 스냅샷을 찍어두면 오염된 환경을 1초 만에 되돌릴 수 있다.

⚠️
VM 탈출 공격

극히 드물지만 VM을 탈출해 호스트를 감염시키는 악성코드도 존재한다. 특히 고급 APT 샘플을 분석할 때는 물리적으로 격리된 머신을 권장한다.

권장 구성

용도 OS 주요 툴
Windows PE 분석 Windows 10 x64 VM x64dbg, Ghidra, pestudio, Process Monitor
Linux ELF 분석 Ubuntu 22.04 VM pwndbg(GDB), Ghidra, strace, ltrace
모바일 분석 Android x86 에뮬레이터 apktool, jadx, Frida, objection
자동화/스크립팅 호스트 또는 Linux VM angr, Frida Python, pwntools

툴 설치 가이드

🔭 Ghidra — NSA 오픈소스 디스어셈블러/디컴파일러

Java 기반이라 Windows/Linux/macOS 모두 동작한다. JDK 17+ 필요.

# JDK 설치 (Ubuntu)
sudo apt install openjdk-17-jdk

# Ghidra 다운로드 후 압축 해제
wget https://github.com/NationalSecurityAgency/ghidra/releases/latest
unzip ghidra_*.zip
cd ghidra_*
./ghidraRun

Windows: ghidraRun.bat 실행. 첫 실행 시 Project 디렉토리를 설정한다.

💡
심화편 예고

Ghidra의 CodeBrowser, 디컴파일러 활용, 스크립팅(Jython/Java API)은 별도 Ghidra 심화 가이드에서 다룬다.

🐛 x64dbg — Windows 메인 디버거

x64dbg.com에서 최신 릴리즈를 다운로드한다. 압축 해제 후 즉시 실행 가능 — 설치 불필요.

# 구조
x64dbg/
├── x32/
│   └── x32dbg.exe    # 32비트 대상
└── x64/
    └── x64dbg.exe    # 64비트 대상

분석 대상의 아키텍처에 맞는 버전을 선택한다. 모르면 DIE로 먼저 확인.

필수 플러그인:

  • ScyllaHide — 안티 디버깅 우회 자동화
  • xAnalyzer — API 호출 자동 주석
  • OllyDumpEx — 메모리 덤프

플러그인은 plugins/ 폴더에 dll을 넣으면 자동 로드된다.

🔎 pestudio & DIE — 정적 식별 툴

실행 전 바이너리 성격을 파악하는 첫 단계 툴이다.

pestudio (winitor.com): PE 파일 전용. 임포트 테이블, 문자열, 엔트로피, 블랙리스트 API를 한 화면에 보여준다.

Detect It Easy (DIE) (github.com/horsicq/Detect-It-Easy): 패커/컴파일러 시그니처 식별. PE, ELF, Mach-O 모두 지원.

# DIE CLI 사용
die.exe target.exe

# 출력 예시
PE64
    Compiler: Microsoft Visual C/C++(2019)[EXE]
    Packer: UPX(3.96)[NRV]

이 정보가 이후 분석 전략 전체를 결정한다. 패커가 탐지되면 먼저 언패킹(Ch.12)이 필요하다.

🪝 Frida — 런타임 동적 계측 프레임워크

Python으로 실행 중인 프로세스에 JavaScript 코드를 인젝션해 함수를 후킹한다. Windows/Linux/Android/iOS 모두 지원.

# 설치
pip install frida-tools

# 기본 사용 — 프로세스 목록 확인
frida-ps -a

# 스크립트 인젝션
frida -l hook.js target.exe

# Android 대상
frida -U -l hook.js com.target.app

frida-server는 타겟 디바이스에 올려야 한다. Android의 경우 루팅된 기기 또는 에뮬레이터 필요.

🤖 angr — Python 바이너리 분석 프레임워크

심볼릭 실행(Symbolic Execution) 기반. "입력이 뭐여야 이 분기에 도달하는가"를 수학적으로 푼다.

# 가상환경 사용 강력 권장 (의존성 충돌 많음)
python -m venv angr-env
source angr-env/bin/activate   # Windows: angr-env\Scripts\activate
pip install angr

# 동작 확인
python -c "import angr; print(angr.__version__)"
⚠️
Windows에서 angr

WSL2 또는 Linux VM에서 설치하는 것을 강력 권장한다. Windows 네이티브 설치는 의존성 문제가 자주 발생한다.

VM 스냅샷 전략

분석 VM을 만들었으면 스냅샷을 찍는 습관을 들인다. 스냅샷은 세 개를 기본으로 유지한다:

  • ①
    Clean Base — OS 설치 직후, 툴 설치 전. 건드리지 않는 베이스.
  • ②
    Tools Installed — 모든 툴 설치 완료 상태. 새 분석을 시작할 때 이 스냅샷으로 복원.
  • ③
    Analysis-N — 분석 세션별로 저장. 같은 샘플로 나중에 돌아올 수 있다.

네트워크 격리 설정

악성코드 분석 중 VM의 C2 통신이 실제 서버에 닿으면 공격자에게 분석 사실이 노출되거나, 의도치 않게 다른 피해자가 생길 수 있다. 두 가지 옵션이 있다:

방식 방법 적합한 상황
완전 격리 VM 네트워크 어댑터를 Host-Only로 설정 네트워크 행위가 필요 없는 분석
가짜 네트워크 INetSim 또는 FakeNet-NG로 DNS/HTTP 응답 시뮬레이션 C2 통신 패턴을 관찰해야 할 때
💡
FakeNet-NG 추천

FLARE팀이 만든 FakeNet-NG는 DNS, HTTP, HTTPS, SMTP 등을 모두 시뮬레이션하고, 모든 요청/응답을 로깅한다. 악성코드가 "정상적인" 네트워크 환경이라고 착각하게 만들어 숨긴 기능을 활성화하는 데 유용하다.
