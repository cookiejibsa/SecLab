Chapter 11 · Part 3 — 동적 분석

안티 디버깅 & 우회

분석을 방해하는 기법들과 그것을 무력화하는 방법

왜 안티 디버깅을 쓰는가

악성코드와 상용 소프트웨어 보호 모두 분석을 어렵게 만들기 위해 안티 디버깅 기법을 쓴다. 종류는 크게 세 가지다: 디버거 탐지, 타이밍 체크, 환경 탐지. 각 기법을 이해하면 우회책이 보인다.

디버거 탐지 기법과 우회

IsDebuggerPresent

PEB(Process Environment Block)의 BeingDebugged 필드를 읽는다.

; 원본 체크 코드
call IsDebuggerPresent
test eax, eax
jnz  exit_program     ; 디버거 감지 시 종료

; 우회 방법 1: jnz → jz 패치
; 우회 방법 2: x64dbg에서 EAX를 0으로 수동 변경
; 우회 방법 3: ScyllaHide 플러그인 (자동 패치)

; 직접 PEB 조작
; 64비트: PEB는 GS:[0x60]
mov rax, gs:[0x60]    ; PEB 주소
mov byte [rax+2], 0   ; BeingDebugged = 0

CheckRemoteDebuggerPresent

NtQueryInformationProcess를 내부적으로 호출해 디버거 연결 여부를 확인한다.

; 우회: ScyllaHide가 자동 처리
; 수동: x64dbg에서 반환값(pbDebuggerPresent 포인터) 값을 0으로 패치

NtGlobalFlag

PEB+0xBC의 NtGlobalFlag가 디버거 하에서 0x70으로 설정된다.

; 체크 코드
mov  eax, [peb+0xBC]
and  eax, 0x70
cmp  eax, 0x70
je   debugger_detected

; 우회: 해당 주소의 값을 0으로 수정

힙 플래그 체크

디버거 하에서 힙 헤더의 ForceFlags와 Flags가 다른 값을 가진다.

; 힙 기준 주소 (PEB에서 힙 포인터 획득)
mov  eax, [peb+0x18]      ; ProcessHeap
cmp  dword [eax+0x40], 0  ; ForceFlags (x86)
jne  debugger_detected

타이밍 기반 탐지

; RDTSC 기반 타이밍 체크
rdtsc                   ; 시작 타임스탬프 → EDX:EAX
mov  esi, eax
; ... 코드 실행 ...
rdtsc                   ; 종료 타임스탬프
sub  eax, esi           ; 경과 사이클
cmp  eax, 0x10000      ; 너무 오래 걸리면 (디버거로 단계 실행)
ja   debugger_detected

; 우회: RDTSC에 BP 걸고 EAX를 일관된 값으로 수정
; 또는 ScyllaHide의 RDTSC 훅 사용

ScyllaHide — 안티 디버깅 자동 우회

x64dbg 플러그인 ScyllaHide는 대부분의 일반적인 안티 디버깅 기법을 자동으로 패치한다.

; 설치: plugins/ 폴더에 ScyllaHide.dp64 복사
; 설정: Plugins → ScyllaHide → InjectionMethod 선택
; 프로파일에서 우회할 기법 체크박스로 선택

; 적용 범위
; ✅ IsDebuggerPresent, CheckRemoteDebuggerPresent
; ✅ NtQueryInformationProcess
; ✅ NtGlobalFlag, Heap Flags
; ✅ RDTSC 훅
; ✅ OutputDebugString 탐지
⚠️
VM 탐지는 별개

CPUID, VMware I/O 포트, Hyper-V 아티팩트로 VM을 탐지하는 기법은 안티 디버깅과 별개다. 이 경우 물리 머신에서 분석하거나, VM 핑거프린트를 지우는 추가 작업이 필요하다.
